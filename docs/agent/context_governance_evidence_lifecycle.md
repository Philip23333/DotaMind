# Context Governance：Runtime 驱动的历史压缩

## 1. 状态、目标与范围

本文同时记录目标设计与当前边界；当前行为以代码和测试为准。
Pi 模式迁移及阶段一至三的确定性验收已完成：Runtime 支持完整请求水位自动压缩、
容量不足出口和一次 provider 溢出恢复，并保留内部显式触发用于测试。
固定合成资料的真实模型评估已启动；真实赛事数据评估、质量结论和参数调优尚未完成。
它替代模型主动更新摘要、独立 release 和高压强制释放 Raw 的旧目标。
旧设计由 Git 历史保留，不增加兼容层。

DotaMind 是学生独立开发的 Dota 2 赛事分析 Agent。第一版追求健壮、小而美、
核心流程闭环和个人可维护性，优先参考成熟实现，仅为实际场景增加必要差异。
主要场景是同一个用户任务中多次查询、artifact.read 和分析消息的累计增长，
同时支持同会话连续追问；不是只处理多轮用户聊天。

术语：一次用户任务从用户提问到最终回答，可包含多次模型调用；
observation 是工具实际返回给模型的内容。后台存储不等于模型已经观察。

当前实现包含专门摘要调用、近期原始历史保留、统一上下文构建、固定容量
Artifact 定位清单、同会话延续、自动水位压缩和单次溢出恢复。
不包含模型主动摘要/release 工具、重要性评分、
按任务完成度选取压缩范围、
多摘要管理、语义记忆检索、模型历史搜索、会话树、后台并行压缩、重启恢复或 subagent。

## 2. 核心决策

| 关注点 | 第一版决策 |
| --- | --- |
| 触发者 | 配置有效窗口时按完整请求水位自动触发；测试也可显式触发 |
| 范围 | 较早连续历史进入摘要，按预算保留近期原始消息 |
| 长单轮 | 允许任务内部切分，不等待任务完成 |
| 当前用户消息 | 本轮始终原文可见，只出现一次；不维护独立的“有效要求”实体 |
| 摘要调用 | 独立 LLM 请求，非新的用户任务或带工具循环的 Agent run |
| 摘要 | 每会话一份当前自然语言摘要，轻量结构提示，完整替换 |
| 切换 | 摘要与历史保留起点一起提交生效；失败保持旧有效状态 |
| 定位线索 | Runtime 从真实工具结果维护固定容量、去重的 FIFO 清单 |
| 恢复 | 复用 artifact.read / artifact.grep，不保证全部历史始终可发现 |
| 连续追问 | 延续有效历史，包括近期工具观察；执行状态按用户请求重建 |
| 生命周期 | 进程内、会话隔离；历史和 Artifact 不因压缩删除 |
| 失败 | 摘要生成与提交分离；候选失败不替换旧状态 |

模型负责语义提炼与业务判断。Runtime 负责顺序、容量、消息协议、状态一致性与
真实定位信息；不审批摘要的语义完整性，也不依赖模型自发在正确时机整理上下文。

## 3. Artifact 与会话记录

沿用 [Artifacts](../ARTIFACTS.md) 的数据路径：普通工具小结果直接可见，
大结果外置为完整、经过校验的逻辑工具输出，再返回有界 observation。
artifact.read 返回限定大小内的实际内容，可多次读取，不再次走通用外置流程。

上下文压缩统一处理小结果、外置预览、read 返回、调用参数和助手消息。
Artifact 控制单次资料交付量，历史压缩控制累计占用，两者不重复调度。
完整 provider 原始响应若未被工具输出保留，不属于此处的恢复承诺。

会话保存线性的原始执行记录、Artifact、压缩记录和定位清单：

- 原始记录包括用户/助手消息、工具调用与实际返回，具有会话归属、请求归属、
  稳定标识、顺序及调用/返回关联。不包含模型未返回的内部思考。
- 大结果完整正文由 Artifact 保存；历史保留实际交付模型的预览和各次读取结果，
  不再复制整个 Artifact。实际返回范围以返回内容为准，不能用请求 limit 代替。
- 消息在执行过程中追加；流式片段不必各占一条历史，中断结果不得当成完整成功响应。
- 压缩记录保存摘要、覆盖范围、保留起点及运行元数据；旧摘要保留在活跃上下文外。
- 正式会话状态不能仅依赖失败 trace 或仅保存用户/最终答案的产品聊天表。

第一版保持进程内会话隔离。删除会话或进程状态丢失后，不承诺恢复旧 Artifact
和摘要；产品聊天文本尚在也不代表旧引用仍有效。不增加隐藏 TTL；观测存储增长，
若需容量限制，明确失败，不静默删掉仍承诺可读的资料。
保存历史用于追溯，不意味着必须增加模型历史搜索工具。

## 4. 正常执行与压缩时序

```text
接纳用户消息 / 完成一批工具返回并记录
  -> 构建下一次模型请求
  -> 检查完整输入与剩余执行预算
       -> 无需压缩：正常调用
       -> 需要压缩：固定范围 -> 历史摘要/复用旧摘要 -> 单轮前缀摘要（若切开轮次）
                       -> 机械合并 -> 一次原子提交 -> 重建请求
  -> 模型返回工具调用：执行、记录，回到检查入口
  -> 模型返回最终答案：记录，本次用户任务结束
```

同一会话串行执行，压缩时暂停该会话的正常推进；不同会话互不阻塞。
切分发生在完整消息边界，不在工具批次未返回时提交，也不截断单条消息正文。
保持工具调用及其返回成组；用确定性消息结构选择合法边界。

切分点若正好位于新一轮用户消息之前，只生成/更新历史摘要；若切分点位于一轮
内部，则将该轮原始用户请求和已移出的早期消息单独总结为轮次前缀。历史摘要调用
接收完整旧摘要与更早历史；轮次前缀调用只接收被切开的那一轮前缀，不混入摘要或
保留消息。两段均成功后才机械合并并一次提交；任一失败都保留旧有效状态。

成功提交同时更新当前摘要与保留起点，例如：

```text
之前：M0 + 消息 1～20
摘要输入：M0 + 消息 1～12
之后：M1 + 消息 13～20
```

不暴露“M1 + 全部旧消息”的重复状态或“M0 + 已裁掉历史”的信息缺口。
原始记录不改写。新请求仍须检查大小，摘要成功不等于空间一定充足。

## 5. 触发与范围

配置有效上下文窗口后，Runtime 在执行、主回答和降级回答阶段均检查完整请求容量；
只有执行和主回答可以按规则触发压缩。显式 `compact_before_steps` 仅供内部测试与
调用使用。`DOTAMIND_COMPACTION_KEEP_RECENT_TOKENS` 是近期原始历史的估算 token 目标，
按 canonical JSON UTF-8 字节数及 `context_estimate_bytes_per_token` 向上换算，不用
provider usage 估算单组消息。完整工具调用/返回组不可拆分；超预算的单组也整体保留。
从最新消息向前累计到目标附近，再选合法切分点；更早历史与旧摘要进入历史摘要，
如切点落在某轮内部，则单独压缩该轮前缀。不按比赛届次、任务完成状态、当前焦点或
业务重要性挑选。

生产水位为严格大于关系：令 `W=context_window_tokens`、
`R=compaction_reserve_tokens`、`E=estimated_input_tokens`，生产触发条件仍为
`E > W-R`（整数阈值 `W-R+1`）。配置窗口时必须满足 `R < W`。

动态输出预算与模型响应失败恢复的权威契约见
[`model_output_and_recovery.md`](model_output_and_recovery.md)。动态输出预算的配置、Runtime、
容量检查和 trace 接线已实现并离线验收；Adapter 已完成工具调用批次的严格解析、整批分类、
失败原文保留及有界诊断。Runtime 的配对未执行结果、纠错和回答截断恢复仍待实现。
当前运行时区分裁剪前的**期望输出上限**和按当前输入空间裁剪后的**实际输出上限**。
测试提前触发的独立配置
`context_compaction_test_trigger_percent=P`（环境变量
`DOTAMIND_CONTEXT_COMPACTION_TEST_TRIGGER_PERCENT`）基于期望输出上限计算：
`A=max(0, W-expected_output_cap-context_safety_margin_tokens)`，
测试阈值为 `ceil(A×P/100)`，最终阈值仍取生产与测试阈值的较小值，因此覆盖只能提前、
不能推迟。实际请求容量检查改用实际输出上限，即
`E+actual_output_cap+safety_margin <= W`。配置上下文窗口时，若仍无足够空间，先沿用
正常容量/压缩流程并在输入变化后重算；`CRITICAL` 硬容量边界优先于 `HIGH` 水位。
没有模型窗口时容量治理关闭，即使设置测试百分比也不会推断窗口。

即使单个用户任务很长，也可压缩其早期查询、读取和分析，保留最近调用继续执行。
系统指令按正常请求构建保留。当前用户消息原文始终可见；若已在保留历史中，
不额外注入。新用户消息到来后，前一条转为普通历史，不再固定保留。
历史目标和限制通过摘要延续，不建立语义化的有效要求清单。

计量包含指令、工具说明、执行状态、当前摘要、定位清单和所有实际消息。
沿用 [Context Accounting](context_accounting.md) 的 UTF-8 字节指标作诊断，
不将其伪装为 token。按配置模型选择合适计数/估算并预留余量；provider usage
可校准，但压缩前的 usage 不得直接当作压缩后占用。
每个摘要请求先完整构造，再以与普通请求相同的 `measure_request_context_bytes()`
计量，包含摘要指令、旧摘要（如有）和对应历史。使用配置的字节/token 比率估算输入：
`I = ceil(context_bytes / B)`。历史摘要输出额度为
`floor(compaction_reserve_tokens × 0.8)`，单轮前缀摘要为
`floor(compaction_reserve_tokens × 0.5)`；设置
`DOTAMIND_COMPACTION_MODEL_MAX_OUTPUT_TOKENS` 时再取两者较小值。窗口已配置时，
仅当 `I + O + S <= W` 才允许发送；不通过减小输出、截断或分块来绕过容量检查。
因此摘要输入不再受独立的固定 256 KiB 限制。

未配置模型窗口时，显式压缩仍可执行，trace 将容量记录为 `fits: null`，不猜测窗口。
超出容量时以 `context_compaction_failed` / `summary_context_capacity_exceeded`
拒绝，`attempt_count=0`；如果同次压缩有多个摘要请求，必须先检查全部请求，任何一个
不合格都不能先调用另一个。容量记录写入 trace 的 `compaction_capacity_checks`，只含
计量和预算字段，不复制历史正文。没有新增历史时复用旧摘要；历史摘要和轮次前缀摘要
仍串行调用并原子提交，摘要调用失败时保留原重试、取消、deadline 和状态边界。

摘要输出额度与输入估算是不同配置边界。默认 reserve 为 16384，它是预算参数，不代表模型
能力。普通模型输出上限通过 `DOTAMIND_MODEL_MAX_OUTPUT_TOKENS` 与可选的
`DOTAMIND_APPLICATION_MAX_OUTPUT_TOKENS` 配置；旧
`DOTAMIND_CONTEXT_OUTPUT_RESERVE_TOKENS` 不再读取，也不映射到新字段。reserve 仍参与
生产触发线和摘要预算推导；不要通过把 reserve 调成窗口的 70% 模拟 30% 测试水位。增加
reserve 可降低摘要被截断的概率，但不能保证摘要一定完成。

## 6. 摘要调用

历史摘要输入是专用指令、完整旧摘要（首次为空）和更早历史。轮次前缀输入保留被
切开轮次的原始用户问题及该轮已移出的消息，不包含旧摘要、历史摘要候选或近期保留
消息；不拿最新用户问题替换原问题。前缀指令只要求说明原始请求、给定片段中的进展
及理解后续消息所需的信息，并明确后续消息另行保留、不可猜测后续进展。两类摘要均
不开放工具、不继续回答原问题、不自行选择压缩范围。工具返回只包含模型实际看过的
observations；不自动加载 Artifact 完整正文。

两种输出分别是完整自然语言摘要候选：

- 当前目标与相关背景；
- 已知事实、阶段结论；
- 限制、矛盾和未知；
- 继续工作的资料线索；
- 未完成事项。

不要求逐项必填，不引入 claim / coverage / dimensions 或结构化知识实体。
在测试证明具体不稳定问题前，不增加此类实体。提示模型纠正旧认识、删除过时内容、
保持简洁；不要求永久保留旧摘要的所有内容。

Runtime 检查调用正常完成、非空、未因输出上限截断；不再按摘要正文 UTF-8 字节数拒绝。
事实、推断和未知的区分是提示与评估要求，不做逐条语义审批。
模型可在正文说明证据关系，但不承担完整抄写、延续全部 Artifact 引用的职责。

## 7. Runtime Artifact 定位清单与恢复

复用工具结果中的真实引用，由 Runtime 维护会话内紧凑清单：

- 固定最多 N 条，按首次登记顺序 FIFO；同一 Artifact 去重，重复访问不刷新优先级。
- 新引用超限时移出最早条目，不做重要性评分。
- 条目包含准确引用、来源工具、有长度上限的查询线索，优先使用已有参数和元数据，
  不调用模型生成描述。装饰性线索可限长，引用本身不能截断为无效值。
- 清单独立于自然语言摘要，由 Runtime 注入并计入请求占用。
- 清单是定位信息，不表示资料全部被观察，也不证明摘要结论。

FIFO 移出不删除 Artifact 或原始历史。摘要或近期消息仍有引用时照常可读。
清单不因摘要改写而被清空，不依赖模型抄写；也不从全部旧历史反复回填已淘汰条目。
N 和单条长度为可调参数；具体数据结构复用现有状态，不建设来源知识库。

恢复使用已有 artifact.read / artifact.grep，产生新 observation 并重新计入占用。
定位线索丢失或小结果没有 Artifact 时，可重新调用业务工具；这产生新观察，
不保证恢复旧快照。无法取得资料时明确不足。第一版不增加来源检索、模型历史搜索，
也不承诺全部旧证据始终可发现；由真实任务评估决定是否需要扩展。

## 8. 请求构建与连续追问

| 请求 | 实际输入 |
| --- | --- |
| 正常执行 | 系统指令、当前摘要、FIFO 定位清单、保留历史、当前用户消息、执行状态与工具 |
| 历史摘要调用 | 摘要指令、旧摘要、更早历史，无业务工具 |
| 单轮前缀调用 | 摘要指令、被切开轮次的原始问题及已移出前缀，无业务工具 |
| 最终回答 | 与执行一致的当前摘要、定位信息和有效历史，加回答指令；按结束路径关闭工具 |

统一投影有效历史，避免旧摘要从工具参数或历史消息再次混入。
确定性的 duplicate / verified full-superset 观察清理可继续作为独立优化，
但只能影响模型上下文投影，不能覆盖原始会话记录；它不代替历史压缩。

新用户消息追加到同一有效历史，保留近期工具 observations 和上一问答案。
不因换了一问清空 Raw 或强制压缩；没有摘要时也不强制补写。
任务计划、完成标记、时间和步数重新建立；摘要和历史任务描述只是背景，
不得自动恢复为新任务执行状态。当前输入占用按实际携带内容重算，不归零。
任务完成不得阻止之后的 Artifact 读取。Artifact read 的 `task_key` 只标记这次
observation 的 checkpoint 来源归属；它不控制 Artifact 是否可读、历史保留或压缩范围，
也不会在读取时重开已完成任务。

`task.checkpoint` 的来源资格按当前请求的有效历史重算：成功的普通内联工具结果
和现有 raw `artifact.read` 观察可作为来源；压缩移除的结果随之失效，仍保留在有效
历史中的结果仍可引用。内联来源和 Artifact read 的任务归属都在工具执行组开始时解析，
不依赖累计 Raw 准入预算；Artifact read 可指定当前计划中已知的任务项，包括已完成项。
归属只供 checkpoint 候选筛选。checkpoint 只保存模型整理的任务状态和来源引用，不代表
事实已验证，不强制创建 Artifact、不改变容量计量，也不释放会话历史中的原始结果；
成功后只消费明确列出的来源，其余来源保留原归属。

## 9. 失败、取消、预算与溢出恢复

- `DOTAMIND_COMPACTION_MAX_RETRIES` 是首次调用之外的摘要重试次数，默认 1、范围 0～3；
  每个摘要段独立计数，采用固定 1/2/4 秒退避。只对适配器明确分类的临时 HTTP、超时和
  网络错误重试，不解析错误文本猜测。重试等待与调用共享原执行/回答阶段 deadline。
- 摘要截断（`finish_reason=length`）、空摘要、非法响应、额度耗尽及其他确定性错误不重试。
  摘要失败或提交版本冲突会停止当前任务并保留原有效历史；两段都成功前不提交任何候选。
  摘要输入超出字节预算时不发起调用。普通业务模型请求不因该配置增加重试。
- 普通模型响应的 Adapter 分类已实现：执行中的工具参数 JSON 非法或带工具调用的响应被截断时，
  Adapter 保留完整拒绝批次并阻止生成有效 ModelResponse；Runtime 仍走现有终止错误出口，尚未写入
  配对错误结果或重试。目标 Runtime 纠错最多再生成两次；连续失败计数在一次正常完整响应后清零。纠错与
  摘要重试分别计数，不共享重试额度，并共同受原执行 deadline 和用户取消约束。详细规则见
  [`model_output_and_recovery.md`](model_output_and_recovery.md)。
- 用户取消停止执行；已提交版本保留，未提交候选丢弃。
- 摘要耗时、token 与费用计入当前用户请求，单独记录维护调用；不重置业务步数
  或时间预算，不绕过 deadline。保留正常回答所需时间。
- 每次真实摘要重试都计入调用记录及评估总调用预算；退避等待不是模型调用，也不增加调用数。
- 压缩后仍不足，不对同一未解决压力反复压缩。正常执行新增内容后可再次触发。
- 能在容量和时间内走现有最终回答路径时，返回已完成部分及限制；否则明确返回
  容量或执行错误。不另建恢复 Agent，也不静默丢弃未成功压缩的历史。

执行阶段和主回答可在有新内容后再次水位压缩；回答阶段的容量降级路径不再尝试
压缩。明确识别的 provider 上下文超限可启动每用户请求最多一次恢复，执行和主回答
共享该额度；摘要调用和降级回答不启动恢复。恢复使用原 step 和阶段 deadline，
只在整次压缩成功后重试失败的业务模型调用，不重放已完成工具。摘要临时错误重试
与这一次溢出恢复是两种独立机制；摘要自身上下文超限不会递归压缩。摘要失败或无
合法压缩范围沿用原阶段失败出口，未提交候选不会进入会话。

三种调用计数保持独立：普通响应纠错按连续失败计算，最多两次补充生成且正常完整响应后清零；
摘要重试按摘要段计算并沿用其现有配置范围；Provider overflow 为每个用户请求最多一次，由执行与
主回答共享。任何机制均不重置原阶段 deadline；overflow 仍按现有一次压缩再试规则，不重跑已经
完成的工具。目标纠错历史中的原调用和配对错误结果组成不可拆分的完整消息组；错误结果不构成
checkpoint 来源。更细规则以 [`model_output_and_recovery.md`](model_output_and_recovery.md) 为准。

正常产品入口从 `DOTAMIND_CONTEXT_WINDOW_TOKENS` 读取容量窗口，并将其传入会话
Runtime。窗口留空时自动容量治理关闭；设置有效窗口并重启服务后启用。生产示例将
`DOTAMIND_CONTEXT_COMPACTION_TEST_TRIGGER_PERCENT` 留空；低成本提前触发测试可设为
`30`。百分比只改变触发时间，不影响摘要输出额度、历史切分、近期保留预算或提交。
旧变量 `DOTAMIND_CONTEXT_COMPACTION_TRIGGER_PERCENT` 不再读取，迁移时应删除。
修改 API 配置后需重启后端；容器部署还需确认实际运行的是新镜像。窗口配置不会推测
所选模型的真实上下文窗口。

## 10. 实施顺序与验收

阶段一、二、三的实现和确定性验收已完成。端到端确定性场景覆盖同一任务内连续
压缩、Artifact FIFO 定位与真实 `artifact.read` 重读、provider 溢出恢复、产品服务
连续追问及摘要失败后继续使用旧有效历史。确定性测试验证机械边界，不代表真实
模型摘要质量已经验证。

Pi 模式迁移与确定性验收完成。阶段四：固定合成资料的真实模型评估已开始；真实赛事
任务评估、摘要质量与追问准确度评审、参数调优及遗留行为清理仍待完成。当前阶段
尚不据此宣称已验证真实赛事效果、稳定质量、成本或延迟，也不在此文档中指定项目通用
模型窗口值或声称服务已经重启。

随相应阶段移除 coverage/dimensions、ACTIVE_RAW 摘要提交门槛、task/checkpoint
控制清理及关闭任务禁止重读等耦合。不增加主动摘要/release 工具或旧管道兼容层。
Checkpoint 如保留，仅承担任务进度语义。

| 场景 | 必须验证 |
| --- | --- |
| 一问中比较三届 TI，多次 read | 无需新用户消息即可压缩并继续；完整 Artifact 不变 |
| 单轮中间切分 | 当前用户原文一次可见，调用与返回完整，近期原始内容保留 |
| 连续多次压缩 | 旧摘要与新压缩历史合并，不遗漏上次保留、此次需压缩的消息，不重复注入 |
| 压缩后反查未写入摘要的细节 | FIFO 线索指向有效 Artifact，可读取并产生新观察 |
| FIFO 超限、重复引用 | 数量及条目长度有界，去重不刷新，不删除资料 |
| 同会话追问 | 近期工具结果直接复用，任务和预算重建 |
| 生成失败、截断、取消 | 未提交不切换，已提交保持一致，无隐式历史丢弃 |
| 模型请求实际溢出 | 一次压缩重试，不重复业务工具，失败不循环 |
| 压缩后仍过大、无可压缩范围 | 明确容量出口，不发送已知超限请求 |
| 跨会话或会话状态丢失 | 隔离读取，不宣称失效资料仍可恢复 |

动态输出预算已完成以下离线验收：空间充足、按当前请求裁剪、无可用输出空间、压缩后重算、
普通阶段预算与 trace 一致、未配置输出上限时不发送模型请求。Adapter 的离线验收已覆盖完整/流式
响应、全批参数分类、length 截断优先级、身份协议错误优先级、原始批次保留与诊断有界。以下
**Runtime 响应恢复**场景仍待验收：

| 待验收场景 | 必须验证 |
| --- | --- |
| 一批两次调用，后一个参数 JSON 非法 | 两个 handler 均未调用；每个调用都有匹配的未执行错误结果 |
| 工具调用响应以 length 结束 | 即使现有参数可解析，整批仍为零执行 |
| 失败调用历史组 | 原始参数字符串与身份保留；配对历史可编码、持久化并压缩，组不可拆分 |
| 连续响应级失败与计数重置 | 最多两次重新生成；中间正常完整响应清零后可重新计数 |
| 取消或执行 deadline | 纠错不重置 deadline；取消和超时按原出口结束 |
| 纠错耗尽 | 已完成 checkpoint 保留；部分回答说明缺口；无任务计划时也不推断完整完成 |
| 主回答和降级回答截断 | 失败 attempt 被替换；降级截断转确定性兜底，不保存截断文本为 canonical final |
| 普通 schema 错误和 provider overflow | 保持现有逐工具反馈和一次压缩恢复，不重放已完成工具 |

以上剩余项仍为 Runtime 设计待验收项。Adapter 分类和动态预算的离线通过不代表 Runtime 历史
恢复已完成，也不代表 Provider 兼容或线上历史响应已验证。

确定性测试验证机械边界；真实模型 traces / evals 验证摘要质量及任务行为。
记录回答正确性/遗漏、完整请求峰值、摘要和定位清单开销、压缩/恢复次数、
重读次数、总 token 与延迟。与未压缩且可运行的任务基线比较。
第一版不承诺摘要无损或任意长任务无限运行。只有实际评估揭示问题才增加机制。

在该固定版本中，AI 类型分别表达 contextWindow、模型 maxTokens 与单次请求
maxTokens。Agent loop 按调用校验参数；一个调用准备失败时可生成该调用的错误结果，
同批其他已准备调用仍可执行。stopReason 为 error 或 aborted 时该 loop 调用终止。
这些实现事实不含 DotaMind 目标中的 Runtime 整批原子拒绝反馈或两次响应纠错。DotaMind Adapter
现已在 Runtime 之前拒绝非法/截断调用批次并保留完整数据；执行历史配对与 Runtime 纠错仍待实现。

DotaMind 保留当前用户原文、现有 Artifact 数据路径、有界 FIFO 定位清单和进程内线性记录。
普通执行仍以连续纠错次数、deadline 与取消为界；没有生产总步数上限。该目标选择整批拒绝
响应级 JSON/截断错误、保留配对的未执行结果、最多两次连续纠错后进入回答阶段；这不是
Pi 默认行为，也不引入 Pi 的会话树或插件框架。
