# Context Governance：Runtime 驱动的历史压缩

## 1. 状态、目标与范围

本文同时记录目标设计与当前边界；当前行为以代码和测试为准。
阶段二已经完成会话压缩的确定性显式触发闭环：Runtime 可在指定业务 step
前生成摘要、原子提交并重建上下文。自动水位触发、真实模型质量评估和溢出恢复
仍是后续阶段目标。
它替代模型主动更新摘要、独立 release 和高压强制释放 Raw 的旧目标。
旧设计由 Git 历史保留，不增加兼容层。

DotaMind 是学生独立开发的 Dota 2 赛事分析 Agent。第一版追求健壮、小而美、
核心流程闭环和个人可维护性，优先参考成熟实现，仅为实际场景增加必要差异。
主要场景是同一个用户任务中多次查询、artifact.read 和分析消息的累计增长，
同时支持同会话连续追问；不是只处理多轮用户聊天。

术语：一次用户任务从用户提问到最终回答，可包含多次模型调用；
observation 是工具实际返回给模型的内容。后台存储不等于模型已经观察。

当前实现包含专门摘要调用、近期原始历史保留、统一上下文构建、固定容量
Artifact 定位清单、同会话延续和 Runtime 内部显式触发的重复压缩。
不包含自动水位触发、溢出恢复、模型主动摘要/release 工具、重要性评分、
按任务完成度选取压缩范围、
多摘要管理、语义记忆检索、模型历史搜索、会话树、后台并行压缩、重启恢复或 subagent。

## 2. 核心决策

| 关注点 | 第一版决策 |
| --- | --- |
| 触发者 | 测试或内部调用传入的 `compact_before_steps`；不提供 HTTP 配置 |
| 范围 | 较早连续历史进入摘要，按预算保留近期原始消息 |
| 长单轮 | 允许任务内部切分，不等待任务完成 |
| 当前用户消息 | 本轮始终原文可见，只出现一次；不维护独立的“有效要求”实体 |
| 摘要调用 | 独立 LLM 请求，非新的用户任务或带工具循环的 Agent run |
| 摘要 | 每会话一份当前自然语言摘要，轻量结构提示，完整替换 |
| 切换 | 摘要与历史保留起点一起提交生效；失败保持旧有效状态 |
| 定位线索 | Runtime 从真实工具结果维护固定容量、去重的 FIFO 清单 |
| 恢复 | 复用 artifact.read / artifact.grep，不保证全部历史始终可发现 |
| 连续追问 | 延续有效历史，包括近期工具观察；执行状态按用户请求重建 |
| 生命周期 | 进程内、会话隔离；历史和 Artifact 不因压缩删除 |
| 失败 | 摘要生成与提交分离；候选失败不替换旧状态 |

模型负责语义提炼与业务判断。Runtime 负责顺序、容量、消息协议、状态一致性与
真实定位信息；不审批摘要的语义完整性，也不依赖模型自发在正确时机整理上下文。

## 3. Artifact 与会话记录

沿用 [Artifacts](../ARTIFACTS.md) 的数据路径：普通工具小结果直接可见，
大结果外置为完整、经过校验的逻辑工具输出，再返回有界 observation。
artifact.read 返回限定大小内的实际内容，可多次读取，不再次走通用外置流程。

上下文压缩统一处理小结果、外置预览、read 返回、调用参数和助手消息。
Artifact 控制单次资料交付量，历史压缩控制累计占用，两者不重复调度。
完整 provider 原始响应若未被工具输出保留，不属于此处的恢复承诺。

会话保存线性的原始执行记录、Artifact、压缩记录和定位清单：

- 原始记录包括用户/助手消息、工具调用与实际返回，具有会话归属、请求归属、
  稳定标识、顺序及调用/返回关联。不包含模型未返回的内部思考。
- 大结果完整正文由 Artifact 保存；历史保留实际交付模型的预览和各次读取结果，
  不再复制整个 Artifact。实际返回范围以返回内容为准，不能用请求 limit 代替。
- 消息在执行过程中追加；流式片段不必各占一条历史，中断结果不得当成完整成功响应。
- 压缩记录保存摘要、覆盖范围、保留起点及运行元数据；旧摘要保留在活跃上下文外。
- 正式会话状态不能仅依赖失败 trace 或仅保存用户/最终答案的产品聊天表。

第一版保持进程内会话隔离。删除会话或进程状态丢失后，不承诺恢复旧 Artifact
和摘要；产品聊天文本尚在也不代表旧引用仍有效。不增加隐藏 TTL；观测存储增长，
若需容量限制，明确失败，不静默删掉仍承诺可读的资料。
保存历史用于追溯，不意味着必须增加模型历史搜索工具。

## 4. 正常执行与压缩时序

```text
接纳用户消息 / 完成一批工具返回并记录
  -> 构建下一次模型请求
  -> 检查完整输入与剩余执行预算
       -> 无需压缩：正常调用
       -> 需要压缩：固定范围 -> 摘要调用 -> 检查并提交 -> 重建请求
  -> 模型返回工具调用：执行、记录，回到检查入口
  -> 模型返回最终答案：记录，本次用户任务结束
```

同一会话串行执行，压缩时暂停该会话的正常推进；不同会话互不阻塞。
切分发生在完整消息边界，不在工具批次未返回时提交，也不截断单条消息正文。
保持工具调用及其返回成组；用确定性消息结构选择合法边界。

成功提交同时更新当前摘要与保留起点，例如：

```text
之前：M0 + 消息 1～20
摘要输入：M0 + 消息 1～12
之后：M1 + 消息 13～20
```

不暴露“M1 + 全部旧消息”的重复状态或“M0 + 已裁掉历史”的信息缺口。
原始记录不改写。新请求仍须检查大小，摘要成功不等于空间一定充足。

## 5. 触发与范围

当前由 `compact_before_steps` 在业务模型调用前显式请求压缩；近期历史预算决定保留多少原始消息。
未来阶段才根据完整请求水位自动选择触发时机。
从最新消息向前累计到保留预算附近，再选合法切分点；更早的连续消息与旧摘要
一起压缩。不按比赛届次、任务完成状态、当前焦点或业务重要性挑选。

即使单个用户任务很长，也可压缩其早期查询、读取和分析，保留最近调用继续执行。
系统指令按正常请求构建保留。当前用户消息原文始终可见；若已在保留历史中，
不额外注入。新用户消息到来后，前一条转为普通历史，不再固定保留。
历史目标和限制通过摘要延续，不建立语义化的有效要求清单。

计量包含指令、工具说明、执行状态、当前摘要、定位清单和所有实际消息。
沿用 [Context Accounting](context_accounting.md) 的 UTF-8 字节指标作诊断，
不将其伪装为 token。按配置模型选择合适计数/估算并预留余量；provider usage
可校准，但压缩前的 usage 不得直接当作压缩后占用。
摘要请求本身也须满足输入/输出边界；不得将已超限历史原样转发给摘要调用。
阈值、近期预算、摘要上限、计数实现留作实现参数，不在架构阶段冻结数值。

## 6. 摘要调用

输入是摘要专用指令、当前用户消息、旧摘要（首次为空）和本次待压缩消息。
当前用户消息可作为摘要目标提供，但避免在该输入中重复复制。
工具返回包含模型实际看过的 observations；不自动加载 Artifact 完整正文。
专门调用不开放工具、不继续解答原问题、不选择压缩范围。

输出是完整新版自然语言摘要，用轻量结构提示组织：

- 当前目标与相关背景；
- 已知事实、阶段结论；
- 限制、矛盾和未知；
- 继续工作的资料线索；
- 未完成事项。

不要求逐项必填，不引入 claim / coverage / dimensions 或结构化知识实体。
在测试证明具体不稳定问题前，不增加此类实体。提示模型纠正旧认识、删除过时内容、
保持简洁；不要求永久保留旧摘要的所有内容。

Runtime 检查调用正常完成、非空、未因输出上限截断及大小合规。
事实、推断和未知的区分是提示与评估要求，不做逐条语义审批。
模型可在正文说明证据关系，但不承担完整抄写、延续全部 Artifact 引用的职责。

## 7. Runtime Artifact 定位清单与恢复

复用工具结果中的真实引用，由 Runtime 维护会话内紧凑清单：

- 固定最多 N 条，按首次登记顺序 FIFO；同一 Artifact 去重，重复访问不刷新优先级。
- 新引用超限时移出最早条目，不做重要性评分。
- 条目包含准确引用、来源工具、有长度上限的查询线索，优先使用已有参数和元数据，
  不调用模型生成描述。装饰性线索可限长，引用本身不能截断为无效值。
- 清单独立于自然语言摘要，由 Runtime 注入并计入请求占用。
- 清单是定位信息，不表示资料全部被观察，也不证明摘要结论。

FIFO 移出不删除 Artifact 或原始历史。摘要或近期消息仍有引用时照常可读。
清单不因摘要改写而被清空，不依赖模型抄写；也不从全部旧历史反复回填已淘汰条目。
N 和单条长度为可调参数；具体数据结构复用现有状态，不建设来源知识库。

恢复使用已有 artifact.read / artifact.grep，产生新 observation 并重新计入占用。
定位线索丢失或小结果没有 Artifact 时，可重新调用业务工具；这产生新观察，
不保证恢复旧快照。无法取得资料时明确不足。第一版不增加来源检索、模型历史搜索，
也不承诺全部旧证据始终可发现；由真实任务评估决定是否需要扩展。

## 8. 请求构建与连续追问

| 请求 | 实际输入 |
| --- | --- |
| 正常执行 | 系统指令、当前摘要、FIFO 定位清单、保留历史、当前用户消息、执行状态与工具 |
| 摘要调用 | 摘要指令、当前用户消息、旧摘要、待压缩历史，无业务工具 |
| 最终回答 | 与执行一致的当前摘要、定位信息和有效历史，加回答指令；按结束路径关闭工具 |

统一投影有效历史，避免旧摘要从工具参数或历史消息再次混入。
确定性的 duplicate / verified full-superset 观察清理可继续作为独立优化，
但只能影响模型上下文投影，不能覆盖原始会话记录；它不代替历史压缩。

新用户消息追加到同一有效历史，保留近期工具 observations 和上一问答案。
不因换了一问清空 Raw 或强制压缩；没有摘要时也不强制补写。
任务计划、完成标记、时间和步数重新建立；摘要和历史任务描述只是背景，
不得自动恢复为新任务执行状态。当前输入占用按实际携带内容重算，不归零。
任务完成不得阻止之后的 Artifact 读取。

## 9. 失败、取消、预算与溢出恢复

- 临时网络错误复用有界请求重试；确定性错误不增加摘要修复循环。
- 空摘要、截断、大小不合规或提交前取消，不切换有效摘要和边界。
- 用户取消停止执行；已提交版本保留，未提交候选丢弃。
- 摘要耗时、token 与费用计入当前用户请求，单独记录维护调用；不重置业务步数
  或时间预算，不绕过 deadline。保留正常回答所需时间。
- 压缩后仍不足，不对同一未解决压力反复压缩。正常执行新增内容后可再次触发。
- 能在容量和时间内走现有最终回答路径时，返回已完成部分及限制；否则明确返回
  容量或执行错误。不另建恢复 Agent，也不静默丢弃未成功压缩的历史。

自动水位判断、provider 容量错误后的单次溢出压缩重试，以及相应失败出口尚未接入。
当前显式压缩失败即结束本次 Runtime 执行；未提交候选不会进入会话。

## 10. 实施顺序与验收

阶段一“会话记录与统一上下文”和阶段二“显式压缩闭环”已完成。阶段二的验收
包括同一任务内连续压缩、Artifact FIFO 定位与真实 `artifact.read` 重读、连续追问、
失败后继续使用旧有效历史，以及维护调用与提交 trace。

阶段三仍待完成：完整请求水位自动触发、自动溢出恢复及其失败边界。
阶段四仍待完成：真实赛事评估、回答质量/成本/延迟比较和删除被替代的行为。
当前确定性测试验证机械边界，不代表真实模型摘要质量已经验证。

随相应阶段移除 coverage/dimensions、ACTIVE_RAW 摘要提交门槛、task/checkpoint
控制清理及关闭任务禁止重读等耦合。不增加主动摘要/release 工具或旧管道兼容层。
Checkpoint 如保留，仅承担任务进度语义。

| 场景 | 必须验证 |
| --- | --- |
| 一问中比较三届 TI，多次 read | 无需新用户消息即可压缩并继续；完整 Artifact 不变 |
| 单轮中间切分 | 当前用户原文一次可见，调用与返回完整，近期原始内容保留 |
| 连续多次压缩 | 旧摘要与新压缩历史合并，不遗漏上次保留、此次需压缩的消息，不重复注入 |
| 压缩后反查未写入摘要的细节 | FIFO 线索指向有效 Artifact，可读取并产生新观察 |
| FIFO 超限、重复引用 | 数量及条目长度有界，去重不刷新，不删除资料 |
| 同会话追问 | 近期工具结果直接复用，任务和预算重建 |
| 生成失败、截断、取消 | 未提交不切换，已提交保持一致，无隐式历史丢弃 |
| 模型请求实际溢出 | 一次压缩重试，不重复业务工具，失败不循环 |
| 压缩后仍过大、无可压缩范围 | 明确容量出口，不发送已知超限请求 |
| 跨会话或会话状态丢失 | 隔离读取，不宣称失效资料仍可恢复 |

确定性测试验证机械边界；真实模型 traces / evals 验证摘要质量及任务行为。
记录回答正确性/遗漏、完整请求峰值、摘要和定位清单开销、压缩/恢复次数、
重读次数、总 token 与延迟。与未压缩且可运行的任务基线比较。
第一版不承诺摘要无损或任意长任务无限运行。只有实际评估揭示问题才增加机制。

## 11. Pi 参考与本项目差异

参考 Pi 默认机制：阈值触发、旧摘要与旧消息迭代总结、近期原始历史、合法切分点、
完整会话记录与当前上下文分离、机械保留文件线索，以及有界的溢出恢复。
参考源码会演进，实现时核对实际版本，不将默认数值或全部扩展能力视为本项目契约。

- [压缩设计](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)
- [摘要与切分](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/compaction/compaction.ts)
- [文件线索](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/compaction/utils.ts)
- [会话与恢复](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/agent-session.ts)

Dotamind 的必要差异：当前用户原文固定可见；现有 Artifact 数据路径；有界 FIFO
定位清单而非无限累计引用；进程内线性记录；每问已有 deadline/步骤约束。
这些选择服务于赛事分析和独立开发成本，不引入 Pi 的会话树或插件框架。
