# DotaMind 进度快照：2026-06-30 17:38

> 本文记录通用 Tool Contract Runtime 与 validator 全流水线改造。

## 本次更新

- 新增轻量通用 Tool Contract Runtime：
  - `ToolDefinition` 增加 `arg_contracts`、`output_paths`。
  - 新增 `AcceptedRef`、`ArgContract`、`OutputPathContract`。
  - `input_model` 继续负责类型和必填字段，`evidence_kinds` 负责 evidence 可产出性。
- 统一引用解析：
  - 新增 `app.agentic.references`，让 validator 和 executor 使用一致的 `$<call_id>.<output_path>` 解析语义。
  - 引用 path 按 `ToolResult.model_dump(mode="json")` 的逐段路径解析。
- 重构 planner/validator：
  - 新增 `render_planner_tools(registry)`，planner prompt 从 registry 契约渲染工具字段、必填/可选、evidence 和可接受引用。
  - `validate_plan_against_catalog()` 改为通用流水线：tool calls、references、args schema、output contract、evidence producibility。
  - `validate_plan_node` 接收 `ToolRegistry`，LangGraph validate node 与 planner 复用同一 validation pipeline。
- 移除旧倾向：
  - 删除 `$resolve_target.data.hero.hero_id` 硬编码。
  - 删除 `draft_advice` 对 `intent=counter_pick` 的强绑定。
  - validator 中不加入 tool-name/arg-name 业务特判；工具特定内容只作为 registry metadata 和测试 fixture 出现。
- 补充首批 metadata：
  - `resolve_hero -> data.hero.hero_id`。
  - STRATZ `hero_id` 参数接受 `resolve_hero.data.hero.hero_id`。
  - `opendota.resolve_team -> data.team.team_id`。
  - OpenDota team `team_id` 参数接受 `opendota.resolve_team.data.team.team_id`。
  - `opendota.team_heroes.matches` 接受 `opendota.team_recent_matches.data.matches`。
