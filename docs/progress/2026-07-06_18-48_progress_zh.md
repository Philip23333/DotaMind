## 修改总结

- **集成层**（[heroes.py](apps/api/app/integrations/stratz/heroes.py)）：新增 `_HERO_SYNERGY_QUERY`（只请求 advantage/disadvantage 的 `with { heroId2 matchCount winCount synergy }`，不请求 vs 避免 over-fetch）；新增 `hero_synergy_matchup` 方法 + `_normalize_synergy_side`（`pair_win_rate=winCount/matchCount`，`target_hero_id` 用入参，集成层不排序）。
- **agentic 层**（[stratz_tools.py](apps/api/app/agentic/tools/stratz_tools.py)）：注册 `stratz.hero_synergy_ranking`（input hero_id/side="with"/take/min_sample_size；handler 复用 `_filter_matchup_rows` 按 synergy desc 排序；evidence kind=`hero_synergy_ranking_row`+`sample_size`；value 含 `pair_win_rate` + `win_rate_basis="ally_pair: winCount/matchCount"` 双写）。
- **planner**（[planner.py](apps/api/app/agentic/planning/planner.py)）：`Supported` 段补 hero ally synergy（队友 X 配合 -> stratz.hero_synergy_ranking，区别于 hero_matchup_ranking 的敌方克制）。

## 关键设计

- 口径区分：synergy 用 `pair_win_rate` + `ally_pair: winCount/matchCount`，**不复用** matchup 的 `matchup_win_rate`（vs 是敌方克制，with 是盟友协同，语义不同）——守住 P0 刚收敛的胜率口径显式化。
- evidence kind 用真实 registry 名 `hero_synergy_ranking_row`/`sample_size`，不用 v2.5 文档旧称 `synergy_win_rate`。
- heroId1 不强依赖（target_hero_id 用入参），防御 live 方向不稳。
