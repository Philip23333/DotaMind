## Goal

Restore the two runtime data sources lost during the environment move and
remove the risk of them existing only in one developer workspace:

- `apps/api/app/data/heroes/dota2_heroes.yaml`
- `apps/api/app/data/patches/7_41d.json`

## Root cause

- Neither file ever entered Git history, so no committed object could restore it.
- The root `.gitignore` pattern `data/` matched `data` directories at any depth
  and ignored all of `apps/api/app/data/`.
- Runtime code required local snapshots, but the repository had no sync script
  to reconstruct them on a new machine.

## Implementation

- Changed the ignore rule to `/data/`, limiting it to the repository-root data
  directory and making canonical API data commit-visible.
- Added `scripts/sync_game_data.py`, an offline generator that reads Valve's
  official Dota 2 datafeed and writes hero constants plus a selected/latest
  patch. The runtime request path neither downloads nor generates data.
- Added `scripts/hero_aliases_zh.yaml`, a reviewable community-alias overlay on
  Valve's official Simplified Chinese names. `ES` remains attached to both
  Earthshaker and Earth Spirit and therefore resolves as ambiguous.
- Generated a 127-hero snapshot with IDs, internal names, English display names,
  official Chinese names, and community aliases.
- Generated the 7.41d snapshot: released at `2026-06-04T07:00:00Z`, 203 changes,
  and source URLs embedded in the JSON. Polarity uses conservative rules and is
  `neutral` when direction is unclear.
- Fixed the patch reader: an explicitly missing version no longer silently
  falls back to latest, and latest uses version-aware ordering instead of plain
  filename lexicographic ordering.
- Documented sources, the sync command, and review boundaries in
  `docs/technical/configuration.md`.
