## 设计边界

- 本次只实现数据源工具层，不接入现有 `/api/v1/query` 链路。
- STRATZ 工具后续应作为 v2.5 Tool Registry 的候选工具注册，而不是继续新增固定服务链路。
- Transport 层统一处理：
  - Bearer token 请求头。
  - 默认 `User-Agent`。
  - GraphQL errors。
  - 非 JSON 响应。
  - 安全日志，避免输出 token。

## 当前验证结果

- `python -m pytest tests/test_stratz_transport.py tests/test_stratz_heroes.py` 通过。
- `python -m ruff check app tests scripts` 通过。
- `python scripts/check_stratz.py --hero-id 25 --take 3` 当前返回：

## 风险与后续

- 当前 STRATZ 真实 endpoint 被 HTTP 层拒绝，返回 HTML 而不是 GraphQL JSON。
- 这说明本地工具实现和 GraphQL 查询结构已经有单测保护，但真实数据源访问仍需要解决 STRATZ token 权限、Cloudflare/API 入口或官方访问要求。
- 后续接入主链路前，需要先让 `check_stratz.py` 在本地稳定返回真实数据。
