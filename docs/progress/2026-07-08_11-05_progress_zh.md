## 新增主设计文档

- 新增 [DotaMind_V3.0_design.md](../design/DotaMind_V3.0_design.md)。
- 文档将产品名统一为 **DotaMind**，并说明历史 `MetaMind` / `METAMIND_*`
  命名仍是待迁移债务。
- 统一版本口径：
  - v2.5 是受约束 Tool Calling 架构底座。
  - V3.0 是当前产品能力阶段，目标是“基础完整功能闭环”。
  - V3.0 必须继续遵守 v2.5 的 `intent` 非路由、validated `tool_calls`
    决定执行路径、evidence-grounded answer 等硬边界。

## 文档覆盖内容

新文档整合了当前项目现状和阶段目标：

- 当前 active API：`POST /api/v1/plan`，调试入口 `/debug/plan`。
- LangGraph `StateGraph(AgentRunState)` 主链路：
  `planner -> validate -> tools -> evidence -> answer -> critic -> response`。
- 模块实现地图：`application`、`agentic/planning`、`agentic/tools`、
  `agentic/evidence`、`agentic/answer`、`agentic/critic`、`agentic/nodes`、
  `integrations`、`config/policy.yaml`。
- 核心数据模型：`ExecutionPlan`、`ToolCall`、`QueryContext`、`ToolResult`、
  `EvidenceGraph`、`AgentRunState`。
- 当前 19 个工具列表与 evidence kind：
  - STRATZ / player / lane / matchup / synergy / position / daily trend tools。
  - OpenDota team / role meta tools。
  - Local patch tools。
- 当前 4 个 output contracts：`natural_language_answer`、
  `patch_impact_report`、`role_meta_report`、`team_recent_report`。
- STRATZ 数据约束、completed-week / day-grain 边界、bracket/rank filter 边界。
- Sample Policy：explicit / strict / relaxed / default 四种模式，以及
  `policy_applied` provenance。
- V3.0 已闭环能力、P0/P1 后续缺口、非目标、测试验收和命名迁移策略。
