# DotaMind 进度快照：2026-06-23 15:03

> 本文记录 v2.5 受约束 Tool Calling 架构设计文档的新增。

## 本次更新

- 新增 `docs/design/DotaMind_MVP_v2.5.md`。
- v2.5 将后续架构方向从当前的 service routing 调整为 constrained Tool Calling。
- 文档明确当前架构与目标架构差异：
  - 当前 Orchestrator 输出 `ReportRequest`，只选择一个预定义服务。
  - 目标 Orchestrator 输出 `ExecutionPlan`，规划多个受约束工具调用。
- 文档定义了：
  - Agent 与 Tool 边界。
  - `ExecutionPlan`、`ToolCall`、`ToolResult`、`EvidenceGraph`。
  - Tool Registry 与 ToolExecutor。
  - Intent 与 required evidence。
  - 当前代码到 v2.5 的迁移清单。
  - 分阶段实施计划。

## 关键决策

- 后续新增复杂能力，例如 counter pick / synergy pick / draft advice，不应继续新增完整固定服务链路。
- 新能力应优先通过新增工具和 Orchestrator plan 组合实现。
- v2.5 保持受约束：LLM 不能直接写 SQL、拼外部 API URL 或无限 replan。
- 旧 endpoint 先保留，后续新增 `/api/v1/agent/run` 作为 agentic envelope。
