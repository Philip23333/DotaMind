# MetaMind 进度快照：2026-07-03 10:21

> 本文记录对 Planner 的 system prompt 做结构性瘦身，并把缺失的「校验失败→错误回灌→重试」闭环补上。核心思路：把 schema 正确性从自然语言下沉到代码（校验器本就齐全），让 prompt 专注语义判断。

## 本次更新

- **render 层去冗余**（`apps/api/app/agentic/planning/contracts.py`）：
  - `render_planner_tools` 删除 `produced_evidence_names_must_be_exact`（与上一行 `evidence_produced` 同值）、每工具的 `rule: Use only allowed_arg_keys...`、accepted_ref 的重复第二行（两行信息合并为一行 `accepts_ref: <from_tool>.<path> (<type>) -> "$<previous_call_id>.<path>"`）。
  - `render_planner_contracts` 删除 `required_evidence_names_must_be_exact`（向每个契约倾倒全部 evidence 名）、每契约的 `rule`、`example` 行（不再渲染 `prompt_example` JSON）；`allowed_evidence` 仅在 `evidence_allowlist` 非 None 时输出，杜绝 `allowed_evidence: null`。
  - `ContractSpec.prompt_example` 字段保留（边界：不动数据模型），加注释标注「渲染层已不再消费」，后续确认无消费者再移除。
- **静态模板重写**（`apps/api/app/agentic/planning/planner.py` 的 `_PLANNER_SYSTEM_PROMPT`）：
  - 保留 `{tools}`/`{contracts}` 占位符与单个 worked example（pair_lane + natural_language_answer + 带 bracket 的 context）。
  - 规则块收紧为：Schema obedience / Scope filters / References / Output contract / Decision。
  - 删掉底部与工具 description 重复的 notes（patch/role_meta/Tool-specific notes）——`hero_matchup_ranking.side` 仅 `vs`、`lane_meta_global` 按 match_count 排序等语义已在各自工具描述里。
  - 体积：**17076 → 10370 字符（-39%）、283 → 209 行（-26%）**。
- **校验重试闭环**（`AgenticPlanner.plan()`）：
  - 改为 `for attempt in range(1 + planner_max_retries)` 循环；`messages` 累积重试 turn。
  - 四类失败可重试：JSON 解析失败、envelope 形状错误（`ValidationError`）、`status="planned"` 但 `plan=None`（形状错误，非有意终态）、plan 校验错误。
  - 有意终态直接返回不重试：`insufficient_tools`、显式 `error`。
  - `is_last_attempt` 守卫：仅在还有后续尝试时才追加 assistant+user 反馈 turn，避免最后一次无谓追加（否则 `planner_max_retries=0` 的 `prompt_messages` 会多出空反馈 turn）。
  - 循环前 `last=None`，每个非返回分支先赋值 `last` 再 continue，循环后 guard 返回，保证 `planner_max_retries=0` 单次失败也有完整返回。
  - 新增辅助 `_append_retry_turns` / `_retry_feedback`（回显模型上一次输出 + 结构化错误列表）。
  - `AgenticPlanner.__init__` 新增 `planner_max_retries: int | None` 入参（None 时回落 policy），兼作测试注入与编程式覆盖。
- **配置**（`apps/api/app/core/config.py`）：新增 `OrchestratorLLMCallPolicy(LLMCallPolicy)` 子类，挂 `planner_max_retries: int = Field(default=2, ge=0, le=5)`；`LLMPolicy.orchestrator` 改用该子类，`hero_analyzer` 仍用 `LLMCallPolicy`，避免污染。`policy.yaml` 无需改（字段有默认值）。
- **测试同步**（`apps/api/tests/`）：
  - `test_agentic_planner.py`：`FakeLLM` 支持 `payload` 为 list（按调用序弹出、可为 Exception 模拟失败）；所有非重试用例显式 `planner_max_retries=0`（单发语义）；更新 prompt 子串断言（删冗余标记断言、新增 `produced/required_evidence_names_must_be_exact not in prompt`）；新增 4 个重试用例。
  - `test_agentic_contracts.py`：同步 4 个 render 直测用例到新输出格式（`accepts_ref:` 单行、`allowed_evidence` 条件输出、删 example 断言）。
