# DotaMind Progress Snapshot: 2026-06-23 16:59

> This snapshot records the minimal v2.5 Tool Registry loop.

## Updates

- Added `apps/api/app/agentic/` as the internal skeleton for constrained v2.5 Tool Calling.
- Added core models:
  - `ExecutionPlan`
  - `ExecutionConstraints`
  - `ToolCall`
  - `ToolResult`
  - `ToolSource`
- Added tool registration and execution:
  - `ToolDefinition`
  - `ToolRegistry`
  - `ToolExecutor`
- Added the first live tool:
  - `stratz.hero_vs_hero_matchup`
  - Input: `hero_id`, `take`, `week`, `bracket_basic_ids`, `match_limit`
  - Output: STRATZ hero matchup advantage / disadvantage data.
- Added a debug runner:
  - `apps/api/scripts/agent_tool_debug.py`
  - Runs a registered tool from the command line and returns a standard `ToolResult`.

## Design Boundary

- This phase does not connect to the legacy `/api/v1/query` flow.
- This phase does not modify the existing `pipeline/orchestrator.py`, `pipeline/retriever.py`, or report generation flow.
- The goal is to establish the minimal tool execution loop before making the Orchestrator emit `ExecutionPlan`.

## Current Capability

The project can now execute a live tool through the standardized path:

```text
ToolCall
  -> ToolRegistry
  -> ToolExecutor
  -> stratz.hero_vs_hero_matchup
  -> STRATZ GraphQL
  -> ToolResult
```

The result includes:

- `status`
- `data`
- `source`
- `latency_ms`
- `error`
- `metadata`
