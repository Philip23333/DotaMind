# MetaMind Progress Snapshot: 2026-06-23 18:07

> This snapshot records the first implementation of the `/api/v1/plan` LLM Planner experiment path.

## Updates

- Added `AgenticPlanner`:
  - `apps/api/app/agentic/planner.py`
  - Uses the existing `LLMProvider.complete_json(...)`.
  - Returns a three-state planning envelope: `planned`, `insufficient_tools`, or `error`.
- Added `PlanService`:
  - `apps/api/app/application/plan_service.py`
  - Does not fallback to the legacy pipeline.
- Added `/api/v1/plan`:
  - Request: `query`, `game`
  - Response: `query`, `game`, `status`, `reason`, `plan`, `tool_results`, `evidence_graph`, `errors`
- Added LLM debug CLI:
  - `apps/api/scripts/agent_plan_llm_debug.py`
- Added tests:
  - `apps/api/tests/test_agentic_planner.py`
  - `apps/api/tests/test_plan_service.py`
  - `apps/api/tests/test_plan_route.py`

## Behavior Boundary

- `/api/v1/query` is unchanged.
- `/debug/chat` is unchanged.
- `/api/v1/plan` is an independent experimental path.
- The planner can only use the currently registered real v2.5 tools:
  - `resolve_hero`
  - `stratz.hero_vs_hero_matchup`
- When tools are insufficient, the response is `status="insufficient_tools"`.
- Legacy team/meta/patch/claim pipelines are not wrapped.
- No final natural-language answer is generated.

## Planner Validation

- Every tool name must be registered.
- `constraints.allow_mock` must be `false`.
- `tool_calls` must not exceed `constraints.max_tool_calls`.
- `stratz.hero_vs_hero_matchup.hero_id` must use:
  - `"$resolve_target.data.hero.hero_id"`
- `counter_pick` plans must include required evidence:
  - `hero_identity`
  - `matchup_win_rate`
  - `sample_size`
- Hardcoded hero IDs, unknown tools, and natural-language tool names are rejected.
