# MetaMind Progress Snapshot: 2026-06-23 15:03

> This document records the new v2.5 constrained Tool Calling architecture design.

## Updates

- Added `docs/design/MetaMind_MVP_v2.5.md`.
- v2.5 shifts the future architecture direction from service routing to constrained Tool Calling.
- The document clarifies the gap between the current and target architectures:
  - Current Orchestrator returns a `ReportRequest` and selects one predefined service.
  - Target Orchestrator returns an `ExecutionPlan` with multiple constrained tool calls.
- The document defines:
  - Agent and Tool boundaries.
  - `ExecutionPlan`, `ToolCall`, `ToolResult`, and `EvidenceGraph`.
  - Tool Registry and ToolExecutor.
  - Intents and required evidence.
  - Migration checklist from current code to v2.5.
  - Phased implementation plan.

## Key Decisions

- Future complex abilities such as counter pick, synergy pick, and draft advice should not add full fixed service pipelines by default.
- New abilities should primarily be implemented by adding tools and letting the Orchestrator compose them through plans.
- v2.5 remains constrained: the LLM must not directly write SQL, build external API URLs, or replan indefinitely.
- Existing endpoints remain compatible first; a future `/api/v1/agent/run` endpoint will expose the agentic envelope.
