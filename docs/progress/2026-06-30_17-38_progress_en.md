# DotaMind Progress Snapshot: 2026-06-30 17:38

> This snapshot records the generic Tool Contract Runtime and validator pipeline migration.

## Updates

- Added a lightweight generic Tool Contract Runtime:
  - `ToolDefinition` now has `arg_contracts` and `output_paths`.
  - Added `AcceptedRef`, `ArgContract`, and `OutputPathContract`.
  - `input_model` remains responsible for argument type and required-field validation, while `evidence_kinds` drives evidence producibility.
- Unified reference parsing:
  - Added `app.agentic.references` so validator and executor share `$<call_id>.<output_path>` parsing semantics.
  - Reference paths are resolved segment by segment against `ToolResult.model_dump(mode="json")`.
- Refactored planner and validator:
  - Added `render_planner_tools(registry)` so planner prompts render tool fields, required/optional status, evidence, and accepted references from registry contracts.
  - Changed `validate_plan_against_catalog()` into a generic pipeline: tool calls, references, args schema, output contract, and evidence producibility.
  - `validate_plan_node` now receives `ToolRegistry`; LangGraph validation and planner validation reuse the same pipeline.
- Removed old coupling:
  - Removed `$resolve_target.data.hero.hero_id` hardcoding.
  - Removed the strong `draft_advice -> intent=counter_pick` binding.
  - No tool-name or arg-name business branch was added to validator logic; tool-specific content lives in registry metadata and test fixtures.
- Added first metadata set:
  - `resolve_hero -> data.hero.hero_id`.
  - STRATZ `hero_id` args accept `resolve_hero.data.hero.hero_id`.
  - `opendota.resolve_team -> data.team.team_id`.
  - OpenDota team `team_id` args accept `opendota.resolve_team.data.team.team_id`.
  - `opendota.team_heroes.matches` accepts `opendota.team_recent_matches.data.matches`.
