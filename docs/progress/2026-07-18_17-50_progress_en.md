# DotaMind Progress Snapshot: 2026-07-18 17:50

## Lightweight Controller vertical cutover

- Replaced the mandatory-ExecutionPlan Planner envelope with a discriminated
  `ControllerDecision`: `direct_answer`, `clarification`, `context_missing`,
  `capability_boundary`, or `tool_plan`.
- LangGraph now starts with `controller_node -> decision_validate_node`. Only
  `tool_plan` enters validate/tools/evidence/answer/critic; no-tool decisions
  create no EvidenceGraph and run no critic.
- Deleted the old `planner_node`, `AgenticPlanner` module, and old test file.
  The Controller lives in `agentic/planning/controller.py`; graph routing never
  reads `intent`.

## Conversation recall and clarification

- Added `ConversationBasis` and a deterministic `conversation_answer_node`.
  User queries, successful entities, and past answer summaries can be read only
  through valid Turn references in the current `state.history` snapshot.
- Social replies may still use Controller free text; recall cannot.
- Turn now stores `missing_fields`, and history rendering preserves the
  clarification question and pending fields. `clarification_required` is not
  treated as a failed-fact turn.
- The API does not expose history, the rendered history block, raw Controller
  output, prompts, retry feedback, or unredacted decision/plan validation errors.

## Tool evidence and terminal states

- Added `ToolDefinition.mandatory_evidence`; all 19 current data tools declare
  their primary result evidence. `sample_size` is deliberately not a universal
  mandatory kind in this release.
- Effective evidence is the union of contract, selected-tool mandatory, and
  original plan evidence. State/API expose the original list, effective list,
  and stable source map separately.
- Sample policy runs once before first catalog/contract validation. Graph
  revalidation does not mutate the plan, metadata, or evidence obligations.
- Registry metadata fails fast once when PlanService is built; each tool plan
  separately validates effective-evidence producibility.
- Top-level results follow deterministic planning/validation/tool/answer/
  evidence/critic priority. Tool errors cannot be hidden by missing evidence,
  and answer errors cannot be hidden by critic failures.

## Documentation and debug UI

- Replaced `Planner层.md` with `Controller层.md`. The debug UI shows only the
  validated public decision, never raw Controller data.
