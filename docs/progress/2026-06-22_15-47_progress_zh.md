# MetaMind 进度快照：2026-06-22 15:47

> 本文记录战队报告时间范围、比赛详情采样、并发限制和缓存策略的调整。

## 本次完成

### 1. 时间范围确定性换算

Retriever 现在按单位换算 Orchestrator 提取的时间范围：

```text
last_10_days   -> 10 days
last_3_weeks   -> 21 days
last_2_months  -> 60 days
last_1_year    -> 365 days
```

无法识别的值仍回退为 30 天。`last_2_months` 不再被错误解析成 2 天。

### 2. 完整窗口与详情样本拆分

战队报告不再使用一个 `match_limit` 截断全部统计：

```text
时间窗口内全部 match summary
  -> 战绩、胜率、比赛时长、对手和样本充足度

最近 match detail 样本
  -> 招牌英雄和英雄池深度
```

默认详情样本为 50 场，单次硬上限为 100 场。即使环境变量配置更大，也不会超过 100。

响应新增：

```json
{
  "matches_in_window": 42,
  "match_details_analyzed": 42
}
```

`/debug/chat` 会显示“窗口比赛”和“详情样本”。

### 3. 详情请求并发限制

比赛详情通过 `asyncio.Semaphore` 分批获取：

```text
默认并发：10
硬并发上限：15
```

单场详情失败仍由聚合逻辑忽略，不会中止其他详情请求。

### 4. 长期比赛详情缓存

`OpenDotaTransport.get()` 现在支持逐请求指定缓存 TTL。普通 OpenDota 数据继续使用 1 小时缓存，历史比赛详情使用 30 天 TTL：

```text
/teams、/players、/heroStats -> 1 hour
/matches/{match_id}         -> 30 days
```

当前缓存仍存放在 API 进程内存中，服务重启后会清空；尚未迁移到 Redis 或其他持久化缓存。

### 5. 配置项

```text
METAMIND_OPENDOTA_MATCH_DETAIL_SAMPLE_SIZE=50
METAMIND_OPENDOTA_MATCH_DETAIL_MAX_SAMPLE_SIZE=100
METAMIND_OPENDOTA_MATCH_DETAIL_CONCURRENCY=10
METAMIND_OPENDOTA_MATCH_DETAIL_CACHE_TTL_SECONDS=2592000
```
