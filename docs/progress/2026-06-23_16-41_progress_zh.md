# MetaMind 进度快照：2026-06-23 16:41

> 本文记录 STRATZ transport 从 `httpx` 切换为 `urllib` 的修复。

## 背景

- 本地浏览器和命令行 `curl.exe` 可以访问 STRATZ GraphQL。
- `httpx` 请求同一 endpoint、同一 token、同一 GraphQL query 时被 Cloudflare 返回 `403 text/html`。
- `urllib` 和 `requests` 均可正常返回 `200 application/json`。

## 本次更新

- `apps/api/app/integrations/stratz/transport.py`
  - 底层 HTTP 请求从 `httpx.AsyncClient` 改为标准库 `urllib.request`。
  - 保留 async `graphql(...)` 接口，通过 `asyncio.to_thread` 执行阻塞请求。
  - 新增 `StratzHTTPStatusError`，用于表达 HTTP 4xx/5xx。
  - 保留 GraphQL error、非 JSON 响应和 token-safe logging。
- `apps/api/scripts/check_stratz.py`
  - 改为捕获 `StratzHTTPStatusError`。
- `apps/api/tests/test_stratz_transport.py`
  - 测试改为注入 fake urllib opener。
  - 增加 HTTP status error 覆盖。
- `apps/api/tests/test_stratz_heroes.py`
  - 使用 fake transport，只测试 hero data normalization。

## 验证

- `python -m ruff check app tests scripts` 通过。
- `python -m pytest tests/test_stratz_transport.py tests/test_stratz_heroes.py` 通过，7 passed。
- `python scripts/check_stratz.py --hero-id 25 --take 3` 已返回真实 STRATZ hero matchup 数据。

## 结论

- STRATZ token、endpoint 和 GraphQL query 均有效。
- 之前本地请求失败的直接原因是 `httpx` 请求形态被 STRATZ/Cloudflare 拦截。
- 当前 STRATZ 数据源工具已经可以通过 `urllib` 获取真实数据。
