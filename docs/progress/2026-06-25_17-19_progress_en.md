## Current Architecture Assessment

The current `/api/v1/plan` flow has already been split into a node-like flow:

```text
AgentGraphRunner
  -> planner_node
  -> validate_plan_node
  -> tool_executor_node
  -> evidence_node
  -> answer_node
  -> critic_node
  -> formatter_node
```

LangGraph runtime is not introduced yet. A full V3 `response_node` and `replan_node` are also not implemented yet.

## Next Priorities

- Split existing OpenDota capabilities into agentic tools instead of copying the legacy team report pipeline.
- Register STRATZ `lane_outcome` to support later lane, synergy, and draft advice evidence.
- Upgrade `formatter_node` into `response_node` later, so the final layer chooses the response type instead of only serializing state.
- Keep the development-stage rules: no fallback, no mock data hiding gaps, and expose insufficient capabilities directly.
