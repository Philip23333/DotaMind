# MetaMind Progress Snapshot: 2026-06-23 13:59

> This document records Critic quality-gate step 2: reviewing reports with EvidenceBundle context and quality rules.

## Updates

- `CriticAgent.review_report` now accepts `report + EvidenceBundle`.
- `ReportPipeline` passes the Retriever bundle into the Critic.
- The Critic now emits warning/failed quality checks without changing API HTTP behavior; issues are exposed through the trace.

## Added Rules

- Mock data rule:
  - `mock_allowed=false`.
  - `patch_impact` using mock data is marked failed.
  - `meta_report` using mock data is marked warning.
- Team freshness rule:
  - Missing `latest_match_at` is warning.
  - Latest match older than 30 days is warning.
  - Latest match older than 90 days is failed.
- Team sample-size rule:
  - `matches_in_window < 5` is failed.
  - `match_details_analyzed < 5` is warning.
- Report confidence rule:
  - `confidence < 0.5` is warning.
  - `confidence < 0.35` is failed.
- Missing/fallback context:
  - Review metadata now includes `data_source`, `sources`, and `missing`.

## Current Boundary

- The next step is to move them into `apps/api/app/config/policy.yaml` with Pydantic validation in `config.py`.
- The API still returns 200; warning/failed status appears only in the `tasks` trace and does not block report output yet.
