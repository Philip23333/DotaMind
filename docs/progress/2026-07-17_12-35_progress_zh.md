## 目标

让 `POST /api/v1/plan` 支持多轮对话：同一 `session_id` 下，planner 能看到最近
N 轮精简摘要，从而解析代词、继承上下文。会话记忆 opt-in：不带 `session_id`
即无状态单轮（与原行为兼容，仅新增 `session_id:null` 响应字段和 planner
prompt 的历史用法说明段）。

## 外部审查 5 个阻断项 —— 全部修订

1. 历史泄露：`_redact_history_from_messages` + `test_session_privacy`
   哨兵断言（上一轮唯一字符串不出现在下一轮 API JSON）。
2. `turn_index` 重复：store 用 `_SessionData.next_turn_index` 单调分配，裁剪不
   重置计数器。
3. 并发：Phase 1 就上 per-session `asyncio.Lock`，覆盖完整事务；并发 append
   测试断言无重复序号。
4. 上界未封死：新增 `turn_query_max_chars` / `history_max_chars`；`query` 加
   `max_length=2000`；`session_id` 用 `UUID` 校验；`context_scope` 用
   `model_dump(mode="json", exclude_none=True)`；policy 全字段 `ge/le` +
   `history_window<=max_turns_per_session` validator；render 从最新轮向前装填。
5. 失败轮标注：`Turn` 增加 `status`/`response_type`/`response_summary`；
   render 对非 ok 轮加 `⚠ 结论不可作为事实依据`。

## 4 个开放项决策

1. session_id：客户端生成 UUID v4，后端 `UUID` 校验；不自动创建会话。
2. 每轮强制重新 resolve；历史实体只帮 planner 理解代词，不作当轮 evidence。
3. scope：保守选择性继承（prompt 规则约束），禁止无条件复制上轮全部 context。
4. 并发锁：Phase 1 就上。
