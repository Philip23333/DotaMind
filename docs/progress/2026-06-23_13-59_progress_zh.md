# DotaMind 进度快照：2026-06-23 13:59

> 本文记录 Critic 质量门第二步：接收 EvidenceBundle 并执行报告质量规则。

## 本次更新

- `CriticAgent.review_report` 现在接收 `report + EvidenceBundle`。
- `ReportPipeline` 会把 Retriever 返回的 bundle 传给 Critic。
- Critic 新增 warning/failed 质量规则，但暂不改变 API HTTP 返回行为，只通过 trace 暴露。

## 新增规则

- Mock 数据规则：
  - `mock_allowed=false`。
  - `patch_impact` 使用 mock 数据时标记为 failed。
  - `meta_report` 使用 mock 数据时标记为 warning。
- Team freshness 规则：
  - `latest_match_at` 缺失时 warning。
  - 最近比赛超过 30 天 warning。
  - 最近比赛超过 90 天 failed。
- Team sample size 规则：
  - `matches_in_window < 5` 标记为 failed。
  - `match_details_analyzed < 5` 标记为 warning。
- Report confidence 规则：
  - `confidence < 0.5` 标记为 warning。
  - `confidence < 0.35` 标记为 failed。
- Missing/fallback 上下文：
  - Review metadata 现在包含 `data_source`、`sources`、`missing`。

## 当前边界

- 阈值目前仍在 `critic.py` 内部常量中。
- 下一步需要把这些阈值迁移到 `apps/api/app/config/policy.yaml`，并在 `config.py` 中做 Pydantic 校验。
- API 仍返回 200；warning/failed 只体现在 `tasks` trace 中，不阻断报告输出。
