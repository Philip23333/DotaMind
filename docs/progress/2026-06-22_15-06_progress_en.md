# DotaMind Progress Snapshot: 2026-06-22 15:06

> This document records the Human-in-the-Loop candidate-selection loop for ambiguous team queries.

## Work Completed

### 1. Stateless Team Selection Contract

`POST /api/v1/query` now accepts an optional structured selection:

```json
{
  "query": "How Team BB play lately?",
  "game": "dota2",
  "team_selection": {
    "team_id": 8255888,
    "team_name": "BB",
    "time_range": "last_30_days"
  }
}
```

Normal natural-language queries still use Orchestrator LLM routing. When `team_selection` is present, `QueryService` skips the LLM and converts the explicit user choice into a structured `team_report` request.

`TeamReportRequest` and the domain `ReportRequest` also accept an optional `team_id`, so natural-language and structured team-report entry points use the same Pipeline.

### 2. Retriever ID Validation

Candidate selection does not run fuzzy name matching again:

```text
team_selection
  -> QueryService structured request
  -> ReportPipeline
  -> Retriever GET /teams (normally cached)
  -> exact team_id validation
  -> OpenDotaTeams.get_report_data(resolved_team=...)
```

A client-supplied `team_id` must exist in the OpenDota team directory. A stale or invalid selection returns:

```text
HTTP 404
error=team_selection_not_found
```

The `409 ambiguous_team` response now carries `time_range`, preserving the original report window after candidate selection.

### 3. Debug Page Interaction Loop

Candidates on `/debug/chat` now include a `查询这个战队` action. Clicking it:

1. Preserves the original query and game
2. Submits the candidate ID, name, and time range
3. Displays the user's selection action
4. Renders the final team report in the same conversation

The deprecated `apps/web` project was not modified.

### Follow-up Fix: Current Roster Filtering

OpenDota `/teams/{team_id}/players` returns both current and historical players and marks the active roster with `is_current_team_member`. The team report previously selected the first five entries ordered by historical games, causing the Xtreme Gaming report to include former players Xm, Dy, and XinQ.

The integration now selects only the first five players where `is_current_team_member is True`. Xtreme Gaming resolves to Ame, Xxs, xNova, NothingToSay, and fy; former players are not used to fill missing roster slots.

## Current Team Query Flow

```text
Initial query
  -> Orchestrator extracts team_name
  -> Retriever deterministic resolution
  -> resolved: retrieve immediately
  -> ambiguous: 409 + candidates + time_range
  -> not_found: 404

Candidate selection
  -> team_selection
  -> skip LLM
  -> Retriever validates team_id
  -> retrieve team report
```
