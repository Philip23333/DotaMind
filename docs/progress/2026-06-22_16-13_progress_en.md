## Policy Coverage

`policy.yaml` now actively controls:

- OpenDota timeout and default cache TTL
- Default team-report time range
- Generic team words, fuzzy threshold, ambiguity delta, candidate count
- Match-detail default sample, maximum sample, concurrency, cache TTL
- Hero result count and minimum public sample
- Hero evidence thresholds, normalization ranges, score weights, tiers
- Default patch, patch result count, neutral score, buff/nerf delta
- Critic evidence and unsupported-signal rules
- Orchestrator and hero Analyzer temperature and max tokens

API request defaults and service-catalog default descriptions also read from Policy.

## Loading and Validation

`config.py` uses:

```text
yaml.safe_load
  -> AppPolicy.model_validate
  -> frozen nested Pydantic models
  -> process-lifetime cache
```

Validation includes:

- Unknown fields are forbidden
- Required fields and numeric ranges
- Default detail sample cannot exceed the maximum
- Partial evidence thresholds cannot exceed supported thresholds
- Hero normalization low values must be lower than high values
- Hero score weights must total 1.0
- Hero tiers must satisfy S > A > B
- The current Policy version must be 1

`DOTAMIND_POLICY_PATH` may point to another absolute YAML file. Policy is cached for the process lifetime, so API restart is required after edits.

## Code Migration

- Retriever assembles OpenDota Transport, Teams, and Heroes from Policy.
- Team Resolver reads matching thresholds, generic words, and candidate limit from Policy.
- Analyzer reads hero count, scoring, evidence, tiers, and LLM parameters from Policy.
- Patch scoring reads neutral score, change delta, and result limit from Policy.
- Critic reads evidence rules from Policy.
- Orchestrator reads defaults and LLM call parameters from Policy.
