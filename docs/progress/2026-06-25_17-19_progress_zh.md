## 当前架构判断

当前 `/api/v1/plan` 已经从线性 service 拆成 node-like flow：

```text
AgentGraphRunner
  -> planner_node
  -> validate_plan_node
  -> tool_executor_node
  -> evidence_node
  -> answer_node
  -> critic_node
  -> formatter_node
```

但当前还没有引入 LangGraph runtime，也还没有完整的 V3 `response_node` / `replan_node`。

## 后续优先级

- 优先把已有 OpenDota 能力拆成 agentic tools，而不是复制旧 team report pipeline。
- 优先注册 STRATZ `lane_outcome`，为后续 lane / synergy / draft advice 做证据基础。
- `formatter_node` 后续应升级为 `response_node`，负责最终输出类型选择，而不仅是 state 序列化。
- 继续保持开发阶段原则：不 fallback、不用 mock 掩盖缺口、能力不足直接暴露。
