# DotaMind Progress Snapshot: 2026-07-17 12:35

> Frontend and replan are out of scope for this round.

## Goal

Enable multi-turn conversation on `POST /api/v1/plan`: under one `session_id`
the planner sees a compact summary of the last N turns so it can resolve
pronouns and inherit context. Session memory is opt-in: without `session_id`
the service is stateless single-turn (backward compatible, apart from a new
`session_id: null` response field and a history-usage rule block in the planner
prompt).

## External review — all 5 blocking items addressed

1. History leak: `_redact_history_from_messages` + `test_session_privacy`
   sentinel assertion (a unique string from turn N is absent from turn N+1's
   API JSON).
2. Duplicate `turn_index`: the store assigns from `_SessionData.next_turn_index`
   monotonically; trimming never resets the counter.
3. Concurrency: per-session `asyncio.Lock` shipped in Phase 1, covering the full
   transaction; a concurrent-append test asserts no duplicate indices.
4. Unbounded prompt/memory: added `turn_query_max_chars` / `history_max_chars`;
   `query` gains `max_length=2000`; `session_id` validated as `UUID`;
   `context_scope` uses `model_dump(mode="json", exclude_none=True)`; every
   policy int has `ge/le` plus a `history_window <= max_turns_per_session`
   validator; the renderer fills from newest turn backwards within budget.
5. Failure-turn labelling: `Turn` gains `status`/`response_type`/
   `response_summary`; the renderer flags non-ok turns as not citable.

## Decisions on the 4 open items

1. session_id: client-generated UUID v4, backend validates as `UUID`; no
   auto-created sessions.
2. Re-resolve every turn; history entities only help the planner read pronouns,
   never serve as current-turn evidence.
3. Scope: conservative selective inheritance (prompt-enforced); no unconditional
   copy of the prior turn's full context.
4. Concurrency lock: shipped in Phase 1.

## Boundaries and known limits

- `InMemorySessionStore` is single-process/worker; multi-worker needs the
  Phase 2 Redis distributed lock.
- No checkpointer / interrupt / human-in-the-loop.
- No replan loop (a separate track).
- No `apps/web` frontend work; `/debug/plan` only for manual testing.
