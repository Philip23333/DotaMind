# DotaMind Progress Snapshot: 2026-07-03 10:21

> This snapshot records a structural slim-down of the Planner's system prompt and adds the missing "validation-failure → feedback → retry" loop. Core idea: push schema correctness out of natural language and into code (the validator already enforces it), so the prompt can focus on semantic judgment.

## Changes

- **Render-layer de-duplication** (`apps/api/app/agentic/planning/contracts.py`):
  - `render_planner_tools` drops `produced_evidence_names_must_be_exact` (identical to the `evidence_produced` line above), the per-tool `rule: Use only allowed_arg_keys...`, and the duplicate second accepted_ref line (two lines merged into one `accepts_ref: <from_tool>.<path> (<type>) -> "$<previous_call_id>.<path>"`).
  - `render_planner_contracts` drops `required_evidence_names_must_be_exact` (which dumped all evidence names into every contract), the per-contract `rule`, and the `example` line (no longer renders `prompt_example` JSON). `allowed_evidence` is emitted only when `evidence_allowlist` is not None, eliminating `allowed_evidence: null`.
  - `ContractSpec.prompt_example` field is kept (boundary: data model untouched) with a comment noting it is no longer rendered; remove later once no consumers remain.
- **Static template rewrite** (`_PLANNER_SYSTEM_PROMPT` in `apps/api/app/agentic/planning/planner.py`):
  - Keeps `{tools}`/`{contracts}` placeholders and a single worked example (pair_lane + natural_language_answer + context with bracket).
  - Rules tightened into: Schema obedience / Scope filters / References / Output contract / Decision.
  - Removed the bottom notes that duplicated tool descriptions (patch/role_meta/Tool-specific notes) — semantics like `hero_matchup_ranking.side` is `vs`-only and `lane_meta_global` sorting by match_count already live in each tool's description.
  - Size: **17076 → 10370 chars (-39%), 283 → 209 lines (-26%)**.
- **Validation-retry loop** (`AgenticPlanner.plan()`):
  - Converted to `for attempt in range(1 + planner_max_retries)`; `messages` accumulates retry turns.
  - Four retryable failure classes: JSON decode failure, envelope shape error (`ValidationError`), `status="planned"` with `plan=None` (shape error, not an intentional terminal state), and plan validation errors.
  - Intentional terminals return immediately without retry: `insufficient_tools`, explicit `error`.
  - `is_last_attempt` guard: feedback turns (assistant + user) are appended only when another attempt follows, so the final attempt does not append a dangling feedback pair (otherwise `planner_max_retries=0` would leave stray turns in `prompt_messages`).
  - `last = None` before the loop; every non-returning branch assigns `last` before `continue`; the post-loop return guards on it, so `planner_max_retries=0` single-shot failures still return a complete result.
  - Added helpers `_append_retry_turns` / `_retry_feedback` (echo the model's prior output + a structured error list).
  - `AgenticPlanner.__init__` gains `planner_max_retries: int | None` (falls back to policy when None), doubling as a test-injection / programmatic override.
- **Config** (`apps/api/app/core/config.py`): added `OrchestratorLLMCallPolicy(LLMCallPolicy)` subclass with `planner_max_retries: int = Field(default=2, ge=0, le=5)`; `LLMPolicy.orchestrator` uses the subclass while `hero_analyzer` stays on `LLMCallPolicy`, avoiding pollution. No `policy.yaml` change needed (field has a default).
- **Tests** (`apps/api/tests/`):
  - `test_agentic_planner.py`: `FakeLLM` accepts a list `payload` (consumed in order, items may be Exceptions to simulate failures); all non-retry tests pin `planner_max_retries=0` (single-shot semantics); prompt-substring assertions updated (removed redundant-marker assertions, added `produced/required_evidence_names_must_be_exact not in prompt`); 4 new retry tests.
  - `test_agentic_contracts.py`: synced 4 render-level tests to the new output format (single `accepts_ref:` line, conditional `allowed_evidence`, dropped example assertion).

## Boundaries

- Graph orchestration and the `validate` graph node are untouched: the planner validates internally and the validate node still re-runs the same `validate_plan_against_catalog`. Kept as a cheap safety net (and the retry depends on the in-planner validation, so it cannot move down to the node).
- LLM provider unchanged; no function-calling or strict json_schema: the planner emits a "multi-call plan + references + context" DAG, which does not map to a single function-call; `json_object` mode suffices.
- Tool data model and `validate_plan_against_catalog` are untouched (the validator is the correctness anchor).
- `ContractSpec.prompt_example` field is kept this round (commented), pending later removal once no consumers remain.
- The live smoke isolates `AgenticPlanner.plan` and does not exercise the full graph (tools/evidence/answer/critic nodes); schedule a separate end-to-end run if needed.
- Console display of the Chinese `reason` field shows mojibake on the Windows terminal — display-only encoding issue; the data is valid (the plan passed pydantic + catalog validation).
