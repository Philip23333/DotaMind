# DotaMind 进度快照：2026-07-18 17:50

## 轻量 Controller 垂直切换

- 用 discriminated `ControllerDecision` 替换了“Planner 必须生成
  ExecutionPlan”的旧 envelope：支持 `direct_answer`、`clarification`、
  `context_missing`、`capability_boundary` 和 `tool_plan`。
- LangGraph 现在先经过 `controller_node -> decision_validate_node`。只有
  `tool_plan` 进入 validate/tools/evidence/answer/critic；所有无工具决策均不创建
  EvidenceGraph、不运行 Critic。
- 删除旧 `planner_node`、`AgenticPlanner` 模块与旧测试文件，Controller 实现位于
  `agentic/planning/controller.py`。Graph 不按 `intent` 路由。

## 会话回忆与 clarification

- 新增 `ConversationBasis` 与确定性 `conversation_answer_node`。用户问题、成功
  实体和过去回答摘要只能从当前 `state.history` 的有效 Turn 引用。
- social 仍允许 Controller 自由文本；recall 不接受 Controller 自由回答。
- Turn 新增 `missing_fields`，历史渲染保留 clarification 问题与待补字段；
  `clarification_required` 不再被当作失败事实轮次。
- 服务端不会在 API 中返回 history、完整历史块、raw Controller output、prompt、
  retry feedback 或未脱敏的 decision/plan validation 错误。

## 工具证据与错误状态

- `ToolDefinition` 新增 `mandatory_evidence`，19 个现有数据工具均声明了主结果
  evidence；首版没有把 `sample_size` 设为统一硬义务。
- effective evidence 为 contract、selected-tool mandatory 与 plan 原始 evidence
  的并集；State/API 分别暴露原始列表、有效列表和稳定来源映射。
- sample policy 在首次 catalog/contract validation 前执行一次；Graph 重复校验
  不再修改 plan、metadata 或 evidence。
- registry 在 PlanService 构建时执行一次 fail-fast 校验；每个 tool plan 再校验
  effective evidence 可产出性。
- 顶层结果采用 planning/validation/tool/answer/evidence/critic 的确定性优先级，
  保证 tool error 不被 missing evidence 覆盖，answer error 不被 critic failure 覆盖。
