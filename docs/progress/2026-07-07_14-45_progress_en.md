## Sample Policy Stage 1

This phase consolidates scattered `min_sample_size` / `min_position_match_count` defaults into a planner-side parameter policy:

- Added `planning.sample_policy` in [policy.yaml](../../apps/api/app/config/policy.yaml), with per-tool `arg/default/relaxed/strict` values.
- Added config models in [config.py](../../apps/api/app/core/config.py): `PlanningPolicy`, `SamplePolicyConfig`, and `SamplePolicyToolEntry`, including `relaxed <= default <= strict` validation.
- Added the Sample Policy rendering/backfill module in [sample_policy.py](../../apps/api/app/agentic/planning/sample_policy.py):
  - `render_sample_policy(policy, registry)` injects the four sample modes and per-tool threshold table into the planner prompt.
  - Rendering validates that each configured tool exists in the registry and that each configured `arg` is a real input-model field, preventing silent config typos.
  - `apply_sample_policy(plan, policy)` backfills the policy `default` when the LLM omits or emits `null` for a sample arg, recording injected values under `plan.metadata["policy_applied"]`.
- Planner integration lives inside [planner.py](../../apps/api/app/agentic/planning/planner.py): `AgenticPlanner.plan()` calls `apply_sample_policy` after envelope parsing and before catalog validation, so `AgenticPlannerResult.plan` is the final plan.
- `ExecutionPlan` now has a `metadata` field for planner-level policy provenance.
- Five STRATZ tool defaults now mirror policy defaults:
  - `stratz.hero_matchup_ranking.min_sample_size`: 2000
  - `stratz.hero_synergy_ranking.min_sample_size`: 2000
  - `stratz.lane_meta_global.min_sample_size`: 1000
  - `stratz.hero_position_stats.min_sample_size`: 1000
  - `stratz.filter_heroes_by_position.min_position_match_count`: 1000

## Behavior Semantics

- Normal counter/synergy recommendations default to high-sample thresholds: 2000 for matchup/synergy.
- If the user explicitly says "at least N matches", the LLM should write N and post-processing does not override it.
- If the user asks for a robust / high-confidence / large-sample read, the prompt instructs the planner to use the strict tier.
- If the user accepts cold / small-sample / edge heroes, the prompt instructs the planner to use the relaxed tier.
- Stage 1 only adds planner parameter policy and default backfill. It does not add critic sparse-sample checks or a critic -> planner retry loop.
