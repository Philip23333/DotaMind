# DotaMind Progress Snapshot: 2026-06-29 15:22

> This snapshot records the `/api/v1/plan` patch tools, Planner contract validation, and Answer Node split.

## Updates

- Added agentic patch tools:
  - `patch.get_records`
  - `patch.hero_changes`
  - `patch.item_changes`
- Patch tools read local `app/data/patches/*.json` files. They do not call external APIs or use mock data.
- Registered patch tools in the default tool registry.
- Added patch evidence kinds to EvidenceGraph:
  - `patch_records`
  - `hero_patch_changes`
  - `item_patch_changes`
  - `patch_buff_count`
  - `patch_nerf_count`
- Planner now has explicit allowed output contracts:
  - `patch_impact_report`
  - `role_meta_report`
  - `team_recent_report`
  - `hero_matchup_report`
  - `draft_advice`
  - `natural_language_answer`
- `meta_list` is now explicitly treated as the structured output-contract whitelist, not a valid `output_contract`.
- `patch_impact_report` validation requires:
  - `patch.get_records`
  - `patch_records` in `required_evidence`
  - `constraints.allow_mock=false`
- Split `AnswerSynthesizer` internally into:
  - `StructuredReportSynthesizer`
  - `NaturalLanguageAnswerSynthesizer`
- Added first-pass structured answer support for:
  - `patch_impact_report`
  - `role_meta_report`
  - `team_recent_report`
  - `hero_matchup_report`
  - `draft_advice`
- `natural_language_answer` uses the existing LLMProvider and must answer only from EvidenceGraph.
- Added node and answer logs:
  - Planner logs intent / output contract
  - validation logs whether the contract is in the meta list
  - tools node logs called tools
  - answer node logs structured vs natural-language branch selection

## Boundaries

- Did not change `/api/v1/query`.
- Did not change `/debug/chat`.
- Did not migrate the legacy report pipeline.
- Did not implement polished full reports; this update only adds the architecture path and minimal structured outputs.
- No fallback and no mock data are used to hide capability gaps.
