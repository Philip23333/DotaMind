## 本次改动

### 数据层

- 新增 [QueryContext](apps/api/app/agentic/models.py) Pydantic 模型，承载
  cross-cutting scope：`bracket`、`week`、`position_ids`、`region_ids`、
  `game_mode_ids`，全部 Optional，`extra="forbid"`。
- `ExecutionPlan` 增加 `context: QueryContext`，`default_factory=QueryContext`。
  Optional + 默认值，与 `constraints` 形态一致——30+ 个 `ExecutionPlan(...)`
  测试站点无需改动。

### 工具签名

- [ToolHandler](apps/api/app/agentic/tools/registry.py) 由
  `Callable[[BaseModel], ...]` 改为
  `Callable[[BaseModel, QueryContext], ...]`。
- [ToolExecutor.execute](apps/api/app/agentic/tools/executor.py) 改为
  `execute(call, context)`。**硬破坏式变更**，无 shim——内部接口，所有调用
  方在本次一并改完。
- [tool_executor_node](apps/api/app/agentic/nodes/tools.py) 传入
  `state.plan.context`。
- 全部 9 个工具 handler 接受 `(args, context)`；不消费 scope 的工具
  （`resolve_hero`、`patch.*`、`opendota.*`）忽略 context。

### STRATZ 工具 input_model 精简

| 工具 | 之前 | 之后 |
|---|---|---|
| `stratz.lane_outcome` | `hero_id, is_with, week, bracket_basic_ids, position_ids` | `hero_id, is_with` |
| `stratz.hero_vs_hero_matchup` | `hero_id, take, week, bracket_basic_ids, match_limit` | `hero_id, take, match_limit` |
| `resolve_hero` | `query` | `query`（不变） |

handler 从 `context.bracket` / `context.week` / `context.position_ids` 取 scope
传给 [StratzHeroes](apps/api/app/integrations/stratz/heroes.py)，并在返回的
`filters` 字典里如实回填——保持 evidence extractor 与下游消费者原行为。

OpenDota 的 `days` / `min_pub_pick` 不上提，它们是工具自身语义、非 cross-tool
scope。

### Planner prompt

[planner.py](apps/api/app/agentic/planning/planner.py) `_PLANNER_SYSTEM_PROMPT`：

- 新增 "Scope filter rules" 段，明确：

  - STRATZ bracket / position 枚举值清单

- JSON 输出模板加入 `context` 块（介于 `output_contract` 与 `tool_calls` 之间）

## 验证

- 全量测试：`python -m pytest` → **152 passed, 1 warning**（比改前多 1 个，
  是 [test_agent_plan_debug.py](apps/api/tests/test_agent_plan_debug.py) 之前
  跳过的，本轮新接进来的）。
- Lint：`python -m ruff check .` → **all checks passed**。
- 手测：`POST /api/v1/plan` 用 "骷髅王和冰魂走一条路怎么样？在传奇分段的胜率怎么样"，
  关键确认：
  - `plan.context.bracket == ["LEGEND_ANCIENT"]`，scope 在 plan 层一次性设置
  - `plan.tool_calls[*].args` **不再含** `bracket_basic_ids`/`position_ids`
  - `stratz.lane_outcome` tool_result 的 `filters` 字典仍正确反映
    `{"bracket_basic_ids": ["LEGEND_ANCIENT"], "is_with": true, ...}`，只是来源
    从 args 改为 context
  - planner 多数情况下只规划一次 `stratz.lane_outcome`（target=SK）。早期
    一次手测偶尔观察到 planner 自发多规划了一次 `lane_aa`（从冰魂侧也查一
    次），但该行为不稳定、无法复现，**不作为本轮成果**——只是说明 LLM 在
    context 解耦后有扩展 plan 的空间，并非保证。
  - AA 行被准确识别（match_count=797, win_rate=0.5797），answer 正确归因到
    `hero_id 42 + hero_id 68`

## 已知 API 响应形态变化

`POST /api/v1/plan` 响应的 `plan` 字段（opaque dict）新增 `context` key。下游
若有解析 `plan.tool_calls[*].args.bracket_basic_ids` 等字段的消费者会失效——
需要改为读 `plan.context.bracket`。本仓库内 `/debug/plan` 页面没硬编码这些
字段，不受影响。
