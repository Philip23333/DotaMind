## Work Completed This Session

### 1. Aggressive Backend Architecture Refactor

Deleted all legacy `agents/`, `services/`, and `tools/` source files and established a new layered architecture:

```
app/
  api/v1/        FastAPI schemas, routes, HTTP↔domain mappers
  application/   QueryService, ReportService, service catalog
  domain/        evidence, task, report dataclasses (pure business models)
  pipeline/      Orchestrator → Retriever → Analyzer → Critic → Formatter
  integrations/  OpenDota client, patch notes reader
  data/          fixtures + patch JSON
  llm/           LLM provider abstraction, prompt loader
  core/          settings
```

Core principles:

- `api/v1/schemas.py` serves only the HTTP layer; business code no longer imports it
- `domain/` defines unified internal models (`EvidenceBundle`, `EvidenceItem`, `ReportRequest`, `ReportResult`, etc.)
- `pipeline/` is the single execution path; all report types go through the same pipeline
- `application/` provides stable use cases; HTTP/CAP/A2A/scheduled jobs all call this layer in the future
- Removed `/api/v1/query/experimental`; `/api/v1/query` is now the canonical entry point

### 2. Orchestrator Upgraded to LLM Function Calling

**Before**: `OrchestratorAgent.plan()` used keyword if-else routing with role hardcoded to offlane.

**After**:

- `plan_query()` is now `async`
- When LLM is available: uses function calling to let the LLM choose `get_meta_report` / `get_patch_impact` / `get_team_report` / `verify_meta_claim` and automatically extract role, patch, team_name, and claim parameters
- When LLM is unavailable or fails: automatically falls back to the original rule-based routing with zero downtime
- Trace indicates whether routing was `"LLM routed to X via function calling"` or `"rule-based"`
- Added `LLMProvider.complete_with_tools()` method supporting OpenAI tools API format

Verified effect:

```
User: "I play position 1, who should I pick?"
LLM: tool=get_meta_report args={'role': 'carry', 'patch': 'latest'}
```

The LLM correctly parsed "position 1" → `carry` instead of hardcoding offlane.

### 3. Analyzer LLM Request Parallelization

**Before**: LLM insight requests for 10 heroes were executed serially, taking ~40 seconds total.

**After**: Uses `asyncio.gather()` to fire all 10 requests concurrently, reducing total time to ~14 seconds (= slowest single request).

### 4. Live Data Toggle

Added `METAMIND_LIVE_DATA_ENABLED` configuration:

- `false` (default): uses mock fixtures, no external API calls
- `true`: enables OpenDota live retrieval

Rationale: avoids OpenDota network timeouts during testing and local development.

Set `METAMIND_LIVE_DATA_ENABLED=true` in `.env`.

## Known Issues

1. **OpenDota role classification imprecise**: `/heroStats` role tags are hero attributes, not actual lane positions. Heroes like Nyx Assassin and Bounty Hunter get misclassified as mid. Consider integrating STRATZ or using `/publicMatches` for real position data.

2. **Intermittent LLM output truncation**: `max_tokens=800` is occasionally insufficient, causing JSON parse failures. The affected hero falls back to empty reasons. Consider raising to 1200.

3. **OpenDota caching**: `CACHE_TTL=3600` (1 hour). If an OpenDota request fails (e.g. timeout), the empty result is cached for 1 hour, during which mock data is returned. Restart the backend to clear the cache.
