# MetaMind Progress Snapshot: 2026-06-23 12:50

> This document records the fix for the `Team BB` resolver selecting an outdated team.

## Issue

For `How Team BB play lately?`, the Orchestrator correctly routed to `team_report` and extracted `team_name=Team BB`, but the Retriever resolved it to OpenDota `team_id=9131584`.

OpenDota currently exposes multiple `BB` candidates:

- `8255888`: `BoomBoys`, tag=`BB`, newer recent match timestamp.
- `9131584`: `BB Team`, tag=`BB`, older recent match timestamp.

The previous scoring logic gave an extra name boost to team-name matches even when the match only happened after stripping generic words such as `Team`. That allowed `BB Team` to outrank the intended tag=`BB` candidate and prevented ambiguity handling.

## Fix

- `RetrieverTool._exact_team_score` now applies the team-name boost only when the full user-provided name matches the team name.
- Generic-stripped matches such as `Team BB -> BB` no longer outrank tag matches.
- Equal scores no longer rely on tuple string comparison to decide the match reason.
- Added a regression test for OpenDota-style `Team BB` data where both `BoomBoys` and `BB Team` are candidates.

## Current Behavior

Using live OpenDota `/teams` data for simulation:

```text
Team BB -> ambiguous
first candidate: team_id=8255888, name=BoomBoys, tag=BB
second candidate: team_id=9131584, name=BB Team, tag=BB
```

This matches the current three-state strategy: resolve automatically only for a unique match; return ambiguous candidates when multiple reasonable candidates exist, then let `/debug/chat` submit the selected `team_id`.
