> tool `input_model`s to the plan level. **Implemented and full tests pass.**

## Changes

### Data layer

- Added [QueryContext](apps/api/app/agentic/models.py) Pydantic model carrying
  cross-cutting scope: `bracket`, `week`, `position_ids`, `region_ids`,
  `game_mode_ids`. All Optional, `extra="forbid"`.
- `ExecutionPlan` gains `context: QueryContext` with
  `default_factory=QueryContext`. Optional + default, same shape as
  `constraints` — ~30 existing `ExecutionPlan(...)` test sites need no change.

### Tool signature

- [ToolHandler](apps/api/app/agentic/tools/registry.py) changed from
  `Callable[[BaseModel], ...]` to
  `Callable[[BaseModel, QueryContext], ...]`.
- [ToolExecutor.execute](apps/api/app/agentic/tools/executor.py) now
  `execute(call, context)`. Hard breaking change, no shim — internal
  interface, all callers updated in this same change.
- [tool_executor_node](apps/api/app/agentic/nodes/tools.py) passes
  `state.plan.context`.
- All 9 tool handlers accept `(args, context)`; tools that don't consume
  scope (`resolve_hero`, `patch.*`, `opendota.*`) simply ignore context.

### STRATZ tool input_models trimmed

| Tool | Before | After |
|---|---|---|
| `stratz.lane_outcome` | `hero_id, is_with, week, bracket_basic_ids, position_ids` | `hero_id, is_with` |
| `stratz.hero_vs_hero_matchup` | `hero_id, take, week, bracket_basic_ids, match_limit` | `hero_id, take, match_limit` |
| `resolve_hero` | `query` | `query` (unchanged) |

Handlers source scope from `context.bracket` / `context.week` /
`context.position_ids` and pass it to
[StratzHeroes](apps/api/app/integrations/stratz/heroes.py). The `filters` dict
each handler emits is still populated (now sourced from context, not args) —
preserving evidence extractor and downstream consumer behavior.

OpenDota's `days` / `min_pub_pick` are NOT lifted; they are tool-specific
semantics, not cross-tool scope.

### Planner prompt

[planner.py](apps/api/app/agentic/planning/planner.py) `_PLANNER_SYSTEM_PROMPT`:

- Added a "Scope filter rules" section: scope filters MUST go on

  lists the STRATZ bracket / position enum values.
- Added a "QueryContext schema" section with per-field type and purpose.
- The JSON output template now includes a `context` block between
  `output_contract` and `tool_calls`.

## Known API Response Shape Change

The `plan` dict in `POST /api/v1/plan` responses gains a new `context` key.
Any consumer parsing `plan.tool_calls[*].args.bracket_basic_ids` (etc.) will
break — they must read `plan.context.bracket` instead. In-repo, the
`/debug/plan` page does not hardcode these fields and is unaffected.
