## 本次完成的工作

### 1. 后端架构激进重构

删除了旧的 `agents/`、`services/`、`tools/` 全部源码，建立全新的分层架构：

```
app/
  api/v1/        FastAPI schema、routes、HTTP↔domain mapper
  application/   QueryService、ReportService、service catalog
  domain/        evidence、task、report dataclass（纯业务模型）
  pipeline/      Orchestrator → Retriever → Analyzer → Critic → Formatter
  integrations/  OpenDota client、patch notes reader
  data/          fixtures + patch JSON
  llm/           LLM provider 抽象、prompt loader
  core/          settings
```

核心原则：

- `api/v1/schemas.py` 只服务 HTTP 层，业务代码不再 import 它
- `domain/` 定义内部统一模型（`EvidenceBundle`、`EvidenceItem`、`ReportRequest`、`ReportResult` 等）
- `pipeline/` 是唯一主执行链路，所有 report 类型都走同一条 pipeline
- `application/` 对外提供稳定 use case，HTTP/CAP/A2A/定时任务未来都调用这一层
- 删除 `/api/v1/query/experimental`，`/api/v1/query` 成为正式主入口

### 2. Orchestrator 升级为 LLM function calling

**之前**：`OrchestratorAgent.plan()` 是关键词 if-else 路由，role 硬编码为 offlane。

**现在**：

- `plan_query()` 变为 `async`
- LLM 可用时：通过 function calling 让 LLM 选择 `get_meta_report` / `get_patch_impact` / `get_team_report` / `verify_meta_claim`，并自动提取 role、patch、team_name、claim 参数
- LLM 不可用或失败时：自动 fallback 到原有规则路由，零中断
- trace 里标注是 `"LLM routed to X via function calling"` 还是 `"rule-based"`
- 新增 `LLMProvider.complete_with_tools()` 方法，支持 OpenAI tools API 格式

已验证效果：

```
用户: "I play position 1, who should I pick?"
LLM: tool=get_meta_report args={'role': 'carry', 'patch': 'latest'}
```

LLM 正确解析了 "position 1" → `carry`，不再硬编码 offlane。

### 3. Analyzer LLM 请求并行化

**之前**：10 个英雄的 LLM insight 请求串行执行，总耗时约 40 秒。

**现在**：使用 `asyncio.gather()` 并发发出 10 个请求，总耗时约 14 秒（=最慢的单个请求）。

## 已知问题

1. **OpenDota 角色分类不精确**：`/heroStats` 的 role tags 是英雄标签，不是实际对局位置。Nyx Assassin、Bounty Hunter 等被误归到 mid。考虑接 STRATZ 或用 `/publicMatches` 按实际位置统计。

2. **LLM 输出偶发截断**：`max_tokens=800` 偶尔不够，导致 JSON 解析失败。该英雄 fallback 到空 reasons。可考虑提高到 1200。

3. **OpenDota 缓存**：`CACHE_TTL=3600`（1小时）。如果 OpenDota 请求失败（如超时），空结果会被缓存 1 小时，期间持续返回 mock。重启后端可清除缓存。

## 下一步建议

按优先级排序：

1. **Critic LLM 审核**：实现 Layer 2 LLM critic，让 Critic 能从语义层面判断 evidence 是否真正支持 claim
2. **Orchestrator retry loop**：Critic reject 后，Orchestrator 决定补数据/重推理/降级输出（Reflexion 模式）
3. **STRATZ 集成**：用真实 lane/position 数据替代 OpenDota 的英雄标签推断
4. **LLM 输出健壮性**：提高 max_tokens、增加 JSON 修复 fallback、加 result cache
5. **持久化**：存 report run 和 verification evidence
