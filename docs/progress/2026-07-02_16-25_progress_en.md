### Key design decisions

- **advantage/disadvantage groups not merged**: their `synergy` directions
  are opposite; merging would produce misleading ordering. Each group is
  sorted and truncated independently; evidence `value.source_side`
  records the source group.
- **lane_meta_global handler-side truncation**: manual test confirmed
  global laneOutcome returns 15,797 rows in LEGEND_ANCIENT. The handler
  filters by `min_sample_size`, sorts by `match_count`, takes
  `highlight_top`. **Only the top-N rows enter ToolResult.data and
  EvidenceGraph.** Returns `total_available` / `returned_count` /
  `selection_policy` (per-tool convention inside `data`, **NOT a
  ToolResult contract field** — avoids the contract-shaped name
  `data_truncation`).
- **`hero_position_stats` XOR**: enforced by a Pydantic
  `@model_validator(mode="after")` on the input_model. No
  `if tool == "stratz.hero_position_stats"` business branch in
  `planning/contracts.py`.
- **`side="vs"` only this version**: the underlying
  `_HERO_VS_HERO_MATCHUP_QUERY` selects only `vs { ... }` sub-fields;
  adding `with { ... }` is a follow-up. The planner prompt notes the
  limitation.
- **lane_meta_global sorts by match_count**: tool description says
  explicitly "returns high-sample lane pair rows, not necessarily
  strongest by win rate". Common pairs ≠ strongest pairs.
