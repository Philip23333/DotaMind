# DotaMind 进度快照：2026-06-29 15:22

> 本文记录 `/api/v1/plan` 的 patch tools、Planner contract 校验和 Answer Node 分层更新。

## 本次更新

- 新增 agentic patch tools：
  - `patch.get_records`
  - `patch.hero_changes`
  - `patch.item_changes`
- patch tools 使用本地 `app/data/patches/*.json`，不请求外部 API，不使用 mock。
- 默认 tool registry 已注册 patch tools。
- EvidenceGraph 新增 patch evidence：
  - `patch_records`
  - `hero_patch_changes`
  - `item_patch_changes`
  - `patch_buff_count`
  - `patch_nerf_count`
- Planner 明确 allowed output contracts：
  - `patch_impact_report`
  - `role_meta_report`
  - `team_recent_report`
  - `hero_matchup_report`
  - `draft_advice`
  - `natural_language_answer`
- `meta_list` 明确为结构化输出契约白名单，不再作为合法 `output_contract`。
- `patch_impact_report` 校验要求：
  - 必须调用 `patch.get_records`
  - `required_evidence` 必须包含 `patch_records`
  - `constraints.allow_mock=false`
- `AnswerSynthesizer` 内部拆分为：
  - `StructuredReportSynthesizer`
  - `NaturalLanguageAnswerSynthesizer`
- 结构化回答第一版支持简略输出：
  - `patch_impact_report`
  - `role_meta_report`
  - `team_recent_report`
  - `hero_matchup_report`
  - `draft_advice`
- `natural_language_answer` 使用现有 LLMProvider，并要求只基于 EvidenceGraph 生成回答。
- 增加 node/answer 日志：
  - Planner 输出 intent / output_contract
  - validation 输出 contract 是否属于 meta_list
  - tools node 输出调用的 tool
  - answer node 输出结构化或自然语言分支

## 边界

- 未修改 `/api/v1/query`。
- 未修改 `/debug/chat`。
- 未迁移旧 report pipeline。
- 未实现完整高质量报告文案，本轮只补齐架构路径和最小结构化输出。
- 不 fallback，不用 mock 掩盖能力缺口。
