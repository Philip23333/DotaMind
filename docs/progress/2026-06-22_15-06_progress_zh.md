# DotaMind 进度快照：2026-06-22 15:06

> 本文记录战队歧义查询的 Human-in-the-Loop 候选选择闭环。

## 本次完成

### 1. 无状态候选选择契约

`POST /api/v1/query` 现在支持可选的结构化选择：

```json
{
  "query": "How Team BB play lately?",
  "game": "dota2",
  "team_selection": {
    "team_id": 8255888,
    "team_name": "BB",
    "time_range": "last_30_days"
  }
}
```

普通自然语言查询仍由 Orchestrator LLM 路由。存在 `team_selection` 时，`QueryService` 跳过 LLM，将用户的明确选择转换为结构化 `team_report` 请求。

`TeamReportRequest` 和领域 `ReportRequest` 也增加了可选 `team_id`，因此自然语言入口和结构化战队报告入口使用同一条 Pipeline。

### 2. Retriever ID 校验

候选选择不会再次执行名称模糊匹配：

```text
team_selection
  -> QueryService structured request
  -> ReportPipeline
  -> Retriever GET /teams（通常命中缓存）
  -> 按 team_id 精确校验
  -> OpenDotaTeams.get_report_data(resolved_team=...)
```

客户端提交的 `team_id` 必须存在于 OpenDota 战队目录。失效或不存在的选择返回：

```text
HTTP 404
error=team_selection_not_found
```

模糊查询的 `409 ambiguous_team` 响应现在携带 `time_range`，候选选择后不会丢失原始时间窗口。

### 3. Debug 页面交互闭环

`/debug/chat` 的候选项现在包含“查询这个战队”按钮。点击后页面：

1. 保留原始 query 和 game
2. 提交候选的 `team_id`、名称和时间范围
3. 显示用户的选择动作
4. 在同一对话中展示最终战队报告

旧 `apps/web` 未修改。

### 后续修正：现役选手过滤

OpenDota `/teams/{team_id}/players` 同时返回现役和历史选手，并使用 `is_current_team_member` 标记当前名单。战队报告此前直接取按历史比赛数排序的前五名，导致 Xtreme Gaming 报告错误包含 Xm、Dy 和 XinQ。

现在只选择 `is_current_team_member is True` 的前五名。Xtreme Gaming 的当前名单会解析为 Ame、Xxs、xNova、NothingToSay 和 fy；历史选手不会用于补足名单。

相关领域测试与服务测试共 21 项通过，Ruff 检查通过。

## 当前战队查询链路

```text
首次查询
  -> Orchestrator 提取 team_name
  -> Retriever 确定性解析
  -> resolved：直接查询
  -> ambiguous：409 + candidates + time_range
  -> not_found：404

候选选择
  -> team_selection
  -> 跳过 LLM
  -> Retriever 校验 team_id
  -> 查询战队报告
```
